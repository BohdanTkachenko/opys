# Terminal UI board

`opys tui` (opt-in `tui` feature, so the default agent build pulls in no ratatui) is an interactive board over the same inventory: filter, sort, edit, close — with file watching and conflict prompts.

Partial because the TUI is the one write surface that does not go through the store: saves validate with the rules engine only (not the full verify set), the status picker can silently resurrect terminal-status docs, and new-doc ID allocation races parallel agents.

## Test plan
- [ ] a TUI save cannot produce a corpus that fails verify — uncovered (known hole, see linked bug)
- [ ] editing an archived doc keeps its terminal status — uncovered (known hole, see linked bug)
- [ ] new-doc ids are re-checked at save time against concurrent writers — uncovered (known hole, see linked bug)

## Manual verification
### Setup
- Build with the feature enabled: cargo build --release -p opys --features tui
- Open a scratch project with a few documents in its inventory
### Procedure
1. Launch the board and filter by status and tag
2. Edit a document body in the form and save
3. Run opys verify in another shell against the same project
### Expectations
- The board reflects external file edits without a restart
- verify exits 0 after every TUI save
