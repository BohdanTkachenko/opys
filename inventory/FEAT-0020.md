# Terminal UI board

`opys tui` (opt-in `tui` feature, so the default agent build pulls in no ratatui) is an interactive, **read-mostly** board over the same inventory: filter, sort, preview, change status, and close — with live file watching. Body edits are delegated to `$EDITOR` (`e`/`Enter`); on return the board runs the auto-sync + verify pass and surfaces any problem in the status line.

Every write goes through a real command core — status changes via `set_status::core` (which offers only the type's non-terminal statuses, so a terminal doc can't be resurrected), close via `close::core` — so the board can no longer produce a corpus the CLI would reject. [TASK-0045 — TUI: cut the built-in editor, spawn $EDITOR instead](TASK-0045.md) removed the old built-in form/textarea editor (the one write surface that bypassed the store, per [BUG-0031 — TUI bypasses write invariants: resurrection, ID race, rules-only saves](BUG-0031.md)), closing the resurrection, ID-race, and rules-only-save holes; in-TUI doc creation is dropped in favour of `opys new`.

Partial because the end-to-end guarantee (no TUI action can leave the corpus failing verify) is exercised only at the unit level, and the README still needs a board screenshot.

## Manual verification
### Setup
- Build with the feature enabled: cargo build --release -p opys --features tui
- Open a scratch project with a few documents in its inventory
### Procedure
1. Launch the board and filter by status and tag
2. Press `space` to change a document's status, and `e` to edit its body in `$EDITOR`
3. Run opys verify in another shell against the same project
### Expectations
- The board reflects external file edits without a restart
- verify exits 0 after every status change, close, and `$EDITOR` save
