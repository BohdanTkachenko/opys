# SQL is read-only; every write is a lifecycle command

## Context

[ADR-0066 — SQL is the internal working representation; markdown stays the truth](ADR-0066.md) made an in-memory SQL database the working representation and, in a
later step, added `opys query --write`: DML against the authoritative tables,
flushed only if the edit introduces no *new* verify problem. It also named the
sharp edge that came with it: raw DML is not lifecycle. `UPDATE docs SET
status = 'done'` edits a column and does not become a `close`.

[ADR-0099 — Lifecycle is config: transitions, history, derived blocked, priority](ADR-0099.md) turns that edge into a contradiction. A transition now has guards
(declared edges) and leaves a record (`history`). A column update does neither,
so the very write path would produce a document that verify then rejects, or,
under the "no worse" gate, would be refused for a reason the user did not ask
about. The promise this repository wants to make is simpler: opys never writes
an invalid state. Hand edits are the user's and verify catches them; the tool's
own writes are always valid.

The other thing `--write` carried was the writable `blocks` projection, a way
to splice edited section text back into a body. It has exactly one caller.

## Decision

`opys query` is read-only. `--write`, the "no worse" gate, and the writable
`blocks` projection are removed; `blocks` remains as a read-only projection.

Bulk edits compose instead of bypassing: `opys list --format ids` piped into a
mutating command that reads ids from stdin, the way `block` already accepts `-`.
Every command that takes one id accepts several, or `-`.

The section splice (`body::apply_section_edits`) stays in the engine. Its new
and only owner is the log command ([FEAT-0105 — `opys log`: append a dated entry to a log section](FEAT-0105.md)).

## Consequences

- Supersedes the `--write` half of [ADR-0066 — SQL is the internal working representation; markdown stays the truth](ADR-0066.md). Everything else it decided (SQL as
  the internal representation, the plan-guarded SELECT surface, the GlueSQL
  rules) stands, so it stays `accepted` with a note, the way [ADR-0082 — The web UI may manage the allowlist within $HOME](ADR-0082.md) amends
  [ADR-0077 — The node serves an explicit allowlist; discovery only suggests](ADR-0077.md).
- [FEAT-0010 — SQL query surface](FEAT-0010.md)'s surface shrinks. Scripts that used `--write` become a pipe.
- The query console in the web UI was read-only already and does not change.
- "Renaming a tag corpus-wide" is now `tags`, `list --tag`, and `tag --remove
  --add` over a pipe, which is three commands instead of one statement. That is
  the price, and it buys every write going through the rules.
