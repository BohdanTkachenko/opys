# Status lifecycles and the rules engine

Each type declares its own `statuses`, `default_status`, and `terminal_statuses`. A type that declares no `transitions` map has no FSM — any status can move to any status — except terminal statuses, which are reached only via `close`; a type that declares one moves only along its edges ([FEAT-0104 — Configured lifecycle: transitions, history, derived blocked, priority](FEAT-0104.md)). Conditional guards (wontfix needs a reason, archived needs a reason, implemented needs a checked test-plan item) are `[[rules]]` in the config, run by one engine at every write point and re-checked by `verify`.
