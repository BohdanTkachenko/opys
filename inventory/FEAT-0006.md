# Status lifecycles and the rules engine

Each type declares its own `statuses`, `default_status`, and `terminal_statuses`. There is no FSM — any status can move to any status — except terminal statuses are reached only via `close`. Conditional guards (wontfix needs a reason, implemented needs a checked test-plan item, blocked needs a reason or blocker) are `[[rules]]` in the config, run by one engine at every write point and re-checked by `verify`.
