# opys-server: embedded web UI

The human surface ([ADR-0050 — Retire the TUI; the web UI over the server is the human surface](ADR-0050.md)). Decided approach — **Svelte 5 + Vite, built
output committed** ([ADR-0078 — Svelte for the web UI; built assets are committed and drift-checked](ADR-0078.md)):

- Sources in `opys-server/ui/` (`package.json`, `vite.config.js`, `src/`).
  Svelte 5 with runes; **not SvelteKit** — a static SPA, no SSR, no adapters.
- `npm run build` emits `opys-server/ui/dist/`, which is **committed** and
  embedded with `include_str!`/`include_bytes!`, served by axum (`GET /` and
  `GET /ui/*` with correct content-types). Hash the asset filenames or serve
  with `Cache-Control: no-cache` — a stale bundle after an upgrade is a
  support question nobody enjoys.
- **The crate build never runs Node.** `cargo install opys`, `cargo build` from
  a checkout, docs.rs and the nix sandbox must all work offline; if `dist/` is
  missing the build fails with a message telling the developer to run the build
  command, never by fetching anything.
- Add a `ui-build` command to the flake devShell (Node pinned there and nowhere
  else) and a CI job that runs the build and fails if `dist/` differs from what
  is committed — same shape as `scripts/sync-versions.sh --check`. Mark
  `ui/dist/**` `linguist-generated` in `.gitattributes`.
- **Zero external requests** — no CDN scripts, no webfonts; the page must work
  offline. Keep the bundle in the tens of kilobytes and note its size in the
  Progress log.

Views (client-side hash routing, e.g. `#/corpus/<cid>/doc/<id>`):

1. **Sidebar**: project groups → corpora (branch label, primary marker), from
   `GET /api/projects`; a red/green verify dot per corpus; auto-refreshes on
   WS events.
2. **Board** (default per corpus): docs grouped into columns by status,
   filter controls for type/tag/text; click-through to the doc view. Data
   from `/docs`.
3. **Doc view**: `body_html` rendered (it is pre-escaped by the server),
   frontmatter chips (status, tags, relations as links), and the action bar:
   status picker (populated from the *type's* statuses minus terminal ones —
   fetch the doc, derive from the config-provided list the API includes),
   tag add/remove, block/unblock by id, close (with confirm dialog noting it
   deletes the file). Actions POST to `/action`; a 422 shows the error
   message inline verbatim.
4. **Query console**: textarea + run button → `/query`, rendered as a table;
   errors shown verbatim; a few canned example queries as buttons.
5. **Union view** per group: the `/union` table — columns per corpus, drifted
   rows highlighted, collision rows marked strongly.
6. **Live**: subscribe to `/api/events`; on `corpus-reloaded`/`action-completed`
   refresh whatever view is active; show a small "reconnecting…" state when
   the WS drops (retry with backoff).

Note for the doc view's status picker: extend the `GET /doc` payload in
`api.rs` with `allowed_statuses` (the type's non-terminal statuses) rather
than teaching the UI about opys.toml — one server-side line, keeps the UI
dumb.

Styling: minimal, readable, dark-mode via `prefers-color-scheme`. No
pixel-perfection — this UI will be iterated after M1; correctness and
robustness first.

Testing: server-side only — assets are served with the right content-types
and non-empty bodies (oneshot tests); the API contract the UI consumes is
already covered by [TASK-0071 — opys-server: read API and WebSocket events](TASK-0071.md)/72/73 tests. Interactive behavior is verified via
the Manual verification section of [FEAT-0058 — opys-server: the always-on node](FEAT-0058.md) at closeout ([TASK-0075 — opys-server: systemd install, docs, and M1 closeout](TASK-0075.md)).

## Progress
- Filed as part of the M1 plan (see [FEAT-0058 — opys-server: the always-on node](FEAT-0058.md)'s Plan section).
- 2026-08-24: two obligations inherited from [TASK-0073 — opys-server: worktree union view](TASK-0073.md), both about the union view.
  First, **filtering the union by status hides one side of a drift**: filters are
  applied per corpus before the merge, so `status=doing` renders a task that is
  `doing` on main and `done` on the branch as `differs: false, only_in: [main]`.
  The interface must say this where the filter lives, or the view quietly lies
  about exactly what it exists to show. Second, the union JSON has a deliberate
  asymmetry a client author needs to know: `Column.error` is omitted when absent,
  while `Cell.status`/`title`/`updated` always serialize, `null` being the
  presence bit. A cell also carries `unknown`, which means *this corpus did not
  answer* — render that differently from an empty cell, which means *this
  document is not here*.
- 2026-08-24: stack changed from vanilla ES modules to Svelte 5 per [ADR-0078 — Svelte for the web UI; built assets are committed and drift-checked](ADR-0078.md).
  The views, routing and API contract above are unchanged — only how they are
  written and packaged. Build-time downloading of a prebuilt bundle was
  considered and rejected there: docs.rs never enables network access for a
  build, and the flake's build sandbox has none either, so it would break both.
- 2026-08-24: implemented. `opys-server/ui/` is a Svelte 5 + Vite SPA (runes, no
  SvelteKit) with all six views; `ui/dist` is committed and embedded, and
  `opys-server/src/assets.rs` serves it at `/` and `/ui/*`. The shell is
  `no-cache` and the content-hashed assets are `immutable`, so an upgrade can
  never leave a stale bundle behind. `GET /doc` gained `allowed_statuses` so the
  status picker never learns about `opys.toml`.
- The pipeline holds the ADR-0078 line, and each half was tested rather than
  assumed. `build.rs` embeds the committed bundle and, when `ui/dist` is absent,
  fails with `run \`ui-build\`… and commit ui/dist` instead of fetching anything —
  verified by moving the directory aside. `cargo build` succeeds with Node
  stripped from `PATH` entirely. `scripts/ui-build.sh` rebuilds from `npm ci`
  against the committed lockfile and `--check` is the CI drift gate, proven to
  fail on drift and pass when in step. The nix fileset now excludes
  `ui/node_modules` (via `maybeMissing`, since a clean checkout has none), or
  every `npm ci` would have rehashed the derivation.
- **The review caught three real bugs, one of which was a foot-gun aimed at the
  repo itself.** `scripts/ui-build.sh` wiped the committed bundle before
  rebuilding, so a typo in a Svelte file would delete `ui/dist` and stop the
  entire workspace compiling — the script now snapshots and restores on any
  failure. The doc view's status picker was an overridable `$derived`, so any
  background refresh silently discarded the status the user had picked,
  including refreshes caused by their own writes. And tags were rendered in a
  *keyed* `{#each}`, which Svelte throws on for duplicate keys — duplicate tags
  round-trip through the store and pass `verify`, so a legal document would have
  crashed the page.
- 23 findings, 8 major, all triaged. The bundle is **103,748 bytes** across three
  files (34 KB gzipped), against a 160 KB ceiling asserted by a test. The served
  bytes contain no external URL that is fetched: the only absolute URLs are
  Svelte error-message strings and XML namespace constants, both proven inert by
  context, and there is no `@font-face`, no `url()`, and no source map. Every
  network call site is same-origin and the WebSocket URL is derived from
  `window.location`, which the Origin/Host guard requires.
- Rendered in a real browser over a scratch corpus: the sidebar lists the corpus
  with a live indicator and its verify count, the board groups 53 documents into
  status columns with type/tag/find filters, and the doc view shows chips,
  relation links, the action bar (status + reason, tag add/remove, blockers,
  and a red close button labelled "this deletes the file") and the rendered body
  with working internal links. No console errors. Interactive exercise of the
  actions belongs to [TASK-0075 — opys-server: systemd install, docs, and M1 closeout](TASK-0075.md)'s manual verification, per this task's own
  testing note.
- Tests: 7 in `tests/assets.rs` (content types, integrity, no-internet audit,
  path-escape refusal, size ceiling). Full CI gate, `msrv`, `sync-versions
  --check` and `ui-build --check` all green.
