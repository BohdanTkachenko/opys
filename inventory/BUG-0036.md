# --reason writes an undeclared field the next verify rejects

## Reproduction
`opys set-status FEAT-0001 partial --reason "half done"` exits 0: `--reason` unconditionally writes `<status>_reason`, but `partial_reason` is not a declared field, so the very next `opys verify` fails with "unknown frontmatter field". Write-time enforcement runs the rules engine but not verify's closed-frontmatter check, so the guard is asymmetric — a successful command produces a red corpus.

## Tasks
- [ ] reject `--reason` when `<status>_reason` is not a declared field for the type
- [ ] test `--reason` against a status with no declared reason field
