# engine: `opys next` and the pick function

[FEAT-0106 — `opys next`: the pick oracle](FEAT-0106.md). Depends on priority ([TASK-0113 — engine: the ordering chain over the priority int](TASK-0113.md)), observations ([TASK-0116 — engine: ttl, max_visits, the stuck predicate, `verify --fix`, exit 3](TASK-0116.md)) and the
branch reader ([TASK-0117 — engine: the gix branch reader, default-on, and the comrak trim](TASK-0117.md)).

Spec:

- `next::pick(corpus, PickQuery { status, type_filter, limit, exclude_occupied
  }) -> PickResult { items, orphaned }`. Pickable: at the status, no live
  blocker, every `requires_link` target not at a releasing status. Ordered by
  the type's chain with effective priority. Each item carries occupancy from
  `git::occupancy` with `stuck` from `observe`.
- `[types.X.limits]` status to `{ n, human }`; `--limit-from-config` reads `n`.
- CLI: `next --status <s> [--type <t>] [-n N] [--json] [--exclude-occupied]
  [--limit-from-config]`. Human output is a table; JSON is a documented,
  stable shape with a `schema` key.
- The skill gains a "reference loop" page: `next --json`, spawn an agent with
  the document as its brief, `set-status` along an edge, `log` a checkpoint.
  One screen. Also a paragraph on why a human node belongs before any status
  that lands on main.
