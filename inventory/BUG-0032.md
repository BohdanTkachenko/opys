# import bypasses terminal-status and required-section guards

## Reproduction
Import a record with `"status":"done"` — accepted, though `new`/`set-status` reject terminal statuses; and no record gets required sections scaffolded or checked, so a section-less import lands on disk and immediately fails `verify`. `build_record` checks status membership and runs the rules engine, but skips the terminal check and section scaffolding that `new` applies.

## Tasks
- [ ] reject terminal statuses in import records (parity with `new`)
- [ ] scaffold missing required sections (or reject records lacking them)
- [ ] integration tests for both
