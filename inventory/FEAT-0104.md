# Configured lifecycle: transitions, history, derived blocked, priority

The lifecycle engine of [ADR-0099 — Lifecycle is config: transitions, history, derived blocked, priority](ADR-0099.md), as the user sees it. A type declares which
status may follow which; every status change is recorded in the document; a
document is blocked because something live blocks it, not because a flag says
so; and any type that declares `priority` is ordered by it.

## Configuration

```toml
[types.task]
statuses          = ["todo", "in-progress", "review", "user-review", "done"]
default_status    = "todo"
terminal_statuses = ["done"]
order_by          = ["priority", "blocks", "id"]   # the tiebreak chain

[types.task.transitions]
todo        = ["in-progress"]
in-progress = ["review", "todo"]
review      = ["done", "in-progress", "user-review"]
user-review = ["done", "in-progress"]

[types.task.fields.priority]
type = "int"                                   # ADR-0095: lower = higher

[types.feature]
releases_blocks = ["implemented", "wontfix", "archived"]
```

A type with no `transitions` keeps today's any-to-any rule. A type with no
`priority` field sorts by the rest of its chain. `releases_blocks` is only
meaningful on types that are never closed; ephemeral types release by
construction.

## Behaviour

- `set-status` refuses an undeclared edge, exits 2, and names the allowed
  targets. `apply --status` refuses the same edges and, unlike `set-status`,
  refuses the equal case too: a composite write asserts a *transition*, so a
  second claimant is told the document is already there. `block` and `unblock`
  never change status.
- Every document carries `history`, a UTC timestamp to status map with
  sub-second keys, written by `new`, `set-status`, `apply --status` and
  `import`. Nothing else writes it, and nothing hand-edits it.
- `verify` checks that the last history entry is the current status, that each
  consecutive pair is a declared edge, that keys strictly increase, and that
  `created` matches the first key. A document without history is a problem.
- Blocked is computed: a live `blocked_by` entry is one that is not struck and
  whose target's status is not in the target type's `releases_blocks`. `list
  --blocked` and `list --unblocked` filter on it; the board and `next` use the
  same predicate.
- Effective priority is the smallest number among a document's own priority and
  those of everything it transitively blocks; an unprioritised document sorts
  after every prioritised one.
- `new --status` no longer exists; `import` seeds a document at a given status
  with a single history entry.
