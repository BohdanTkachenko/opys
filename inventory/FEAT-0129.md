# Block-level in-place editing and block diffs (svelte-blockdown)

The document body is edited where it is shown. It renders as top-level blocks
(paragraphs, headings, single list items, code blocks, tables); a double-click
turns one block into its markdown source in place, with the caret on the
clicked word; arrow keys at a block's edge move into the next block, Enter on
an empty last line starts a new block, Backspace at the start joins it to the
one above. Clicking outside the document saves through `edit-body`, kept only
if verify stays clean ([ADR-0128 — The document editor is our own block editor, published as svelte-blockdown](ADR-0128.md)). A task checkbox ticks with a click and saves
straight away; a refused tick is reverted on screen.

The editor is the `svelte-blockdown` package (`packages/blockdown/`), reusable
outside opys: no opys imports, no bundled renderer, frontmatter-aware (a
leading YAML fence is its own block, drawn as a key/value table), with a
`BlockdownDiff` component (split or inline, word-level highlights in changed
blocks, unchanged runs folded, and a built-in Side by side / Inline switch) for document history ([FEAT-0124 — Document history and diffs in the web UI](FEAT-0124.md)) and a
selection `toolbar` snippet that reports the selection's source range for
inline comments ([FEAT-0126 — Inline comment threads: a human-agent review loop](FEAT-0126.md)). Blocks are rendered by the node's
`POST /api/render`, with the document view's own comrak options.

## Test plan

- [x] segmentation follows CommonMark block starts — `blocks.test.js::each top-level list item is a block, with its nested content`
- [x] ranges are exact and splicing leaves other bytes alone — `blocks.test.js::ranges exclude the line break, and splicing touches nothing else`
- [x] a leading frontmatter fence is its own block — `blocks.test.js::a leading frontmatter fence is one block`
- [x] block diffs pair edited blocks as changed — `diff.test.js::an edited block is changed, an inserted one added, a dropped one removed`
- [x] unrelated blocks stay a removal plus an addition — `diff.test.js::unrelated blocks at one spot are a removal and an addition`
- [x] the render endpoint uses the body's options and keeps raw HTML escaped — `api::render_turns_blocks_into_the_bodys_html`
- [ ] double-click, caret placement, arrow navigation, new block, join, save on leaving, checkbox tick and refused-tick revert in a browser — manual (verified with Playwright against a node) until a browser harness exists
- [ ] `BlockdownDiff` in split and inline modes, switched by its own control, with folding — manual (verified with Playwright in a Vite harness)
