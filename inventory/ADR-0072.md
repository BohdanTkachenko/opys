# Role kinds describe workers and choose the initial queue

## Context

Role queues need a useful first selection without treating any role name as
special. People, AI agents, and deterministic scripts all own workflow stages.
This extends the metadata decision in
[ADR-0068 — Statuses are owned by declared roles; a role is only a name](ADR-0068.md).

## Decision

A role may declare `kind = "human"`, `"agent"`, or `"automation"`. Human means
a person, agent means an AI agent doing the work, and automation means a
deterministic script. Omission is unknown for backward compatibility. Names
never imply a kind. Kind changes no ownership, ranking, authentication, claims,
or worker dispatch behavior.

Expose project-local kinds in the role directory. A cross-project role has a
kind only when every declaring project agrees on the same known kind; keep
conflicting declarations on their respective project entries.

A role URL selects its explicit role. Otherwise use a remembered role available
in the current scope, then the first human role in alphabetical role order,
then the first available role. Empty directories keep the picker empty.
Remember actual role selections in browser storage.

## Consequences

Existing configs and untyped-role API shapes remain valid. Invalid kinds are
parse errors. A person can name their role anything; defaults no longer
hardcode a user name. Older Opys versions reject kind declarations, so update
project CLI pins before adding the metadata.
