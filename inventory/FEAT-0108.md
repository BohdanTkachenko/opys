# Time-aware verify: stuck, visits, `--fix`

Verify learns two observations that are not content problems ([ADR-0101 — Verify observes time: stuck, visits, `--fix`, and exit code 3](ADR-0101.md)): a
document that has sat in a status longer than its type allows, and one that has
re-entered a status more often than its type allows. It reports them apart from
problems, exits `3` when they are all it found, and with `--fix` performs the
configured transitions itself.

## Configuration

```toml
[types.task.ttl]
in-progress = "10m"        # a fast project; "2y" is equally valid elsewhere
review      = "2d"

[types.task.max_visits]
review = { limit = 3, then = "user-review" }

[types.task.transitions]
in-progress = ["review", "todo", "stuck"]
stuck       = ["in-progress", "todo"]   # the recovery edge autofix relies on
```

`config validate` checks that every `ttl` target and every `then` target is a
declared status with an edge back to a working status.

## Behaviour

- Stuck: the last history key is older than the status's `ttl`. Overflow: the
  number of history entries at a status exceeds its `limit`. Both are one
  engine predicate used by verify, `next` and the flow view.
- `verify` prints observations under an `Observations` heading after problems.
  Exit `0` clean, `1` problems, `2` error, `3` only observations.
- `verify --fix` moves each stuck document to its `ttl` target and each
  overflowed one to its `then`, as ordinary transitions with history and the
  sync pass, then reports what remains. Nothing else is fixable.
- `OPYS_NOW` overrides the clock for tests and reproducible CI.
- In server mode the node verifies with `--fix` semantics by default;
  `autofix = false` in `server.toml` disables it ([TASK-0119 — opys-server: ref reader, occupancy in the union, `next` endpoint, autofix](TASK-0119.md)).

## Test plan
- [ ] a document past its `ttl` is reported as stuck and the exit code is 3 when nothing else is wrong
- [ ] a content problem plus a stuck document exits 1
- [ ] `--fix` transitions the stuck document, appends history, relocates the file, and exits 0
- [ ] the fourth entry into a status with `limit = 3` is refused by `set-status` and named as overflow by verify; `--fix` moves it to `then`
- [ ] `OPYS_NOW` makes the result independent of the wall clock
- [ ] `config validate` rejects a `ttl` target with no edge back to a working status
- [ ] verify's observation output is byte-stable and separate from the problems block
