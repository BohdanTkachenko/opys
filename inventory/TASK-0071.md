# opys-server: read API and WebSocket events

The typed HTTP surface over the registry + actors, plus the event stream. All
JSON. Errors are always `{"error": "<message>"}` with status 400 (bad input),
404 (unknown cid/doc), or 500 (internal). No auth (localhost bind is the
boundary in M1). **No endpoint may execute commands or accept paths** — the
route surface below is exhaustive for this task.

Routes (axum, `opys-server/src/api.rs`; `AppState = { registry, actors,
events }`):

- `GET /api/health` → `{ok, version}` (exists since [TASK-0067 — opys-server: scaffold the AGPL crate](TASK-0067.md)).
- `GET /api/projects` → `[{key, name, corpora: [{cid, root, base, branch,
  is_primary, doc_count, verify_problems, loaded_at, error?}]}]` — registry +
  per-actor cached counts; a corpus whose config failed to parse appears with
  its `error` and no counts.
- `GET /api/corpus/{cid}/docs?type=&status=&tag=` → `[{id, type, status,
  title, tags, path, updated}]` (actor `Docs`; filters AND-combined, each
  optional).
- `GET /api/corpus/{cid}/doc/{docid}` → `{id, type, status, title, tags,
  fields, references, blocked_by, blocks, body, body_html, path, updated}`
  (actor `Doc`; 404 when absent).
- `POST /api/corpus/{cid}/query` body `{sql, params?: [string]}` →
  `{columns, rows}` or 400 with the engine's error message (actor `Query`;
  SELECT-only is enforced by the engine's plan guard — do not re-implement
  it, and do add the test that a `DELETE` is refused end-to-end).
- `GET /api/corpus/{cid}/verify` → `{problems: [string], loaded_at}`.
- `GET /api/events` → WebSocket. On connect, send one `{"type":"hello",
  "version":…}` frame; then forward every broadcast event as JSON
  (`corpus-reloaded`, `corpus-added`, `corpus-removed`, and later
  `action-completed` from [TASK-0072 — opys-server: action endpoint through the command cores](TASK-0072.md)). Server pings every 30 s; a client that
  misses two pings is dropped. A slow client that lags the broadcast buffer
  is dropped (use `tokio::sync::broadcast` lag error), never blocks others.

Testing:

- Handler tests via `tower::ServiceExt::oneshot` against an `AppState` built
  over fixture corpora — no network: projects shape, docs filters, doc 404,
  query happy path, query rejects `DELETE` (400, message mentions SELECT),
  verify payload.
- One end-to-end WS test: bind on port 0, connect with `tokio-tungstenite`
  (add as dev-dep), touch a doc file, assert a `corpus-reloaded` frame
  arrives ≤3 s.

  react to the registry file) and `Manager::rescan` (the expensive allowlist

  `main.rs` and needs replacing with the registry, on the way to `opys web`.
- The actor API to build against: `CorpusHandle::{docs, doc, query, verify,
  reload}` all take `&self` and block on a channel, so call them inside
  `tokio::task::spawn_blocking`. `docs`/`doc`/`verify` answer from cache
  (microseconds); `query` refreshes projections first (milliseconds).
  `DocView` already carries `fields` and `body_html`, and `VerifyStatus` carries
  `load_error` for a corpus whose config stopped parsing — that is the
  `error?` case in `/api/projects`.
- 2026-08-24: implemented. `opys-server/src/api.rs` holds every route, the JSON
  error shape, and the WebSocket; `main.rs` now builds the `Manager` from the
  allowlist, rescans at startup, drives the 60 s and 3600 s passes on the
  blocking pool, and serves. `run` lost its `roots` argument per ADR-0077 and
  gained `--config`; `bind` resolves flag → allowlist file → `127.0.0.1:6797`,
  and a malformed `bind` is fatal rather than silently ignored. Two seams were
  added to `actor.rs`: a `CorpusClient` (Clone + Send + Sync) so a handler never
  holds the manager lock while blocking on an actor, and a `Stats` request so
  `/api/projects` costs one round trip per corpus instead of shipping every
  summary.
- **Four things were added beyond the spec; all are deliberate.** The first is
  security-load-bearing: **an `Origin`/`Host` guard** in front of every route.
  "Localhost bind is the boundary" does not survive contact with the user's own
  browser — a WebSocket handshake is not subject to the same-origin policy at
  all, and DNS rebinding makes an attacker's page same-origin with the node for
  the rest of the API. The review proved it live: a handshake carrying
  `Origin: https://evil.example` and `Host: evil.attacker.test` got `101
  Switching Protocols` and started receiving events. The node now requires a
  loopback `Host` (unless bound off-loopback deliberately) and a same-site
  `Origin` when one is sent. The other three are smaller: a per-corpus timeout
  so one reloading corpus cannot stall the whole project list, `started` on
  `/api/health`, and JSON 404/405 fallbacks so *every* response obeys the
  `{"error": …}` contract.
- Adversarial review (four lenses: contract, guardrails, concurrency, tests)
  returned 24 findings, 8 major, all since fixed. Two were real production bugs
  neither the spec nor the tests would have caught. Handlers took the
  `std::sync::Mutex<Manager>` on a reactor thread, so any request landing during
  a background pass blocked the executor — proven with a scratch test where an
  unrelated 50 ms timer fired 1.55 s late; the lock now lives inside the
  blocking task. And the WebSocket ping used tokio's default
  `MissedTickBehavior::Burst`, so after any stall longer than two ping periods
  the missed ticks fired back to back and dropped the client before it could
  ever pong — now `Delay`. The rest: extractor rejections were escaping the JSON
  error shape as `text/plain` (422/415 outside the documented set), and query
  failures that were the *server's* fault were reported as 400 bad input.
- Two review findings were about the tests rather than the code, and both were
  proven by mutation: the verify assertions were vacuous (every fixture corpus
  was clean, so they held whether or not the API carried problems at all) and
  the spec-required `?tag=` filter was pinned by nothing. The fixtures now
  include a corpus with a real verify problem and one whose config does not
  parse, and both gaps are covered.
- Also fixed a **pre-existing flaky test** this work surfaced:
  `refresh_drops_a_corpus_whose_project_vanished` raced the actor thread, whose
  load calls `create_dir_all(base)` and could recreate the directory the test
  was deleting. Reproduced at 21 failures in 192 runs under contention; zero
  after synchronising on a read first.
- Dogfooded live over this repo: the node served 56 documents with
  `verify_problems: 0`, filters AND-combined (`?type=adr&status=accepted` → 11),
  `FEAT-0058` came back with its `references`/`blocks` maps and escaped
  `body_html`, a parameterised `SELECT` worked, `DELETE FROM docs` was refused
  400 with the engine's own message, and a real WebSocket client received
  `hello` then `corpus-reloaded` after a doc was touched. With the node warm,
  `opys verify` still ran clean — the lock discipline holds outside the tests.
- Tests: 13 API handler, 3 WebSocket, 27 unit, plus the existing suites. Full CI
  gate and `msrv` green. New dev-deps `tokio-tungstenite` and `futures-util`
  pinned to versions already in the lock, so no crates were added.
