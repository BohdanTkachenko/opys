# opys-server: read API and WebSocket events

The typed HTTP surface over the registry + actors, plus the event stream. All
JSON. Errors are always `{"error": "<message>"}` with status 400 (bad input),
404 (unknown cid/doc), or 500 (internal). No auth (localhost bind is the
boundary in M1). **No endpoint may execute commands or accept paths** — the
route surface below is exhaustive for this task.

Routes (axum, `opys-server/src/api.rs`; `AppState = { registry, actors,
events }`):

- `GET /api/health` → `{ok, version}` (exists since [TASK-0067 — opys-server: scaffold the AGPL crate](TASK-0067.md)).
- `GET /api/projects` → `[{key, name, corpora: [{cid, root, base, branch,
  is_primary, doc_count, verify_problems, loaded_at, error?}]}]` — registry +
  per-actor cached counts; a corpus whose config failed to parse appears with
  its `error` and no counts.
- `GET /api/corpus/{cid}/docs?type=&status=&tag=` → `[{id, type, status,
  title, tags, path, updated}]` (actor `Docs`; filters AND-combined, each
  optional).
- `GET /api/corpus/{cid}/doc/{docid}` → `{id, type, status, title, tags,
  fields, references, blocked_by, blocks, body, body_html, path, updated}`
  (actor `Doc`; 404 when absent).
- `POST /api/corpus/{cid}/query` body `{sql, params?: [string]}` →
  `{columns, rows}` or 400 with the engine's error message (actor `Query`;
  SELECT-only is enforced by the engine's plan guard — do not re-implement
  it, and do add the test that a `DELETE` is refused end-to-end).
- `GET /api/corpus/{cid}/verify` → `{problems: [string], loaded_at}`.
- `GET /api/events` → WebSocket. On connect, send one `{"type":"hello",
  "version":…}` frame; then forward every broadcast event as JSON
  (`corpus-reloaded`, `corpus-added`, `corpus-removed`, and later
  `action-completed` from [TASK-0072 — opys-server: action endpoint through the command cores](TASK-0072.md)). Server pings every 30 s; a client that
  misses two pings is dropped. A slow client that lags the broadcast buffer
  is dropped (use `tokio::sync::broadcast` lag error), never blocks others.

Testing:

- Handler tests via `tower::ServiceExt::oneshot` against an `AppState` built
  over fixture corpora — no network: projects shape, docs filters, doc 404,
  query happy path, query rejects `DELETE` (400, message mentions SELECT),
  verify payload.
- One end-to-end WS test: bind on port 0, connect with `tokio-tungstenite`
  (add as dev-dep), touch a doc file, assert a `corpus-reloaded` frame
  arrives ≤3 s.
