# The dashboard is an installable web app

Live testing found no way to give the dashboard its own window: the node
served a page, not an app. It now ships a web app manifest, icons (an SVG, a
192px PNG, a 512px maskable PNG for Android, an Apple touch icon) and a
service worker, so a browser offers *Install* and the installed app opens in
its own window.

The worker caches the UI and never the API: documents come from the node or
not at all ([ADR-0051 — Files and git are the only truth; the server is a view](ADR-0051.md)). Navigations to `/` go to the network first, so an
upgraded node's shell always wins while the node is up, and fall back to the
cached shell when it is down, which then says the node is not answering and
reconnects. Hashed assets under `/ui/` are cache-first (their URLs are
immutable), and each fresh shell prunes the cached assets it no longer
references.

The files live in `ui/public/` and are served at the root from a fixed list,
`assets::ROOT_FILES`; the worker has to sit at `/` to control `/`. Every other
root path is still the JSON 404. Browsers only register a worker in a secure
context: loopback qualifies, so the default bind installs; plain HTTP on any
other address keeps working but cannot install.

## Test plan

- [x] the manifest, icons and worker are served from the root, revalidated, under the right types — `assets::the_app_manifest_and_worker_are_served_from_the_root`
- [x] the root route serves nothing beyond the list — `assets::the_root_route_serves_only_the_listed_files`
- [x] every file in `ui/public` is on the list, and every listed file is bundled — `assets::every_root_file_is_listed`
- [ ] installability and offline launch in a browser — manual (verified with Playwright/Chromium: `Page.getInstallabilityErrors` empty, the page is controlled after a reload, and with the network off a reload still mounts the app) until a browser harness exists
