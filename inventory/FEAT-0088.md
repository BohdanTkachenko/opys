# Edit documents in place from the web UI

Obsidian-style editing for document bodies: an Edit toggle on the document
view swaps the rendered markdown for its source in a textarea, and Save sends
the new `edit-body` typed action. The engine core (`commands/edit.rs
body_core`) replaces the body, re-derives the title from the new first heading,
stamps `updated`, and keeps the result **only if it introduces no new verify
problems** — the same contract `opys query --write` gives SQL edits. A refusal
flushes nothing and is shown verbatim in the UI, with the draft intact.

The action vocabulary stays a closed enum ([ADR-0077 — The node serves an explicit allowlist; discovery only suggests](ADR-0077.md)): `edit-body` carries an id
and a body, never a path.

The body is editable *by default*: clicking anywhere in the rendered prose
opens the source editor with the caret dropped on the clicked section (mapped
back through the nearest heading's source line). Links still navigate,
selections still copy; the Edit button remains the keyboard path.

Custom frontmatter fields are editable in place too, via `set-field` /
`remove-field` (two actions on purpose — with a nullable value, a client that
forgot the field would silently delete one). The engine core
(`commands/edit.rs field_core`) parses the value exactly as the CLI's
`--field key=value` (YAML scalar else string) and runs the same verify gate,
so the closed-frontmatter invariant, declared types, and enum/pattern
constraints refuse with verify's own messages. Keys a dedicated path owns
(`status`, `tags`, the relation maps, `updated`, `blocked_from`) are refused
by name; `created` is an ordinary edit. The doc payload carries the type's
`declared_fields` so the UI can offer enum selects and suggest declared-but-
unset keys without reading `opys.toml` itself.

The frontmatter panel is the whole write surface; the separate action bar is
gone. Status is a menu on its own row that writes on choice — the same gesture
as dragging a card between columns — and a refusal for want of a
`<status>_reason` opens a reason box on the row, holding the picked status, so
the second attempt is one line of typing. Tags and blockers grow from an
inline box at the end of their chips (Enter writes, the chip's × removes;
`block`/`unblock` rewrite both sides). Close is a quiet last row with its
confirmation in place. A control apart from the fact it changes has to explain
which fact that is, and that explanation was the first thing a reader scrolled
past to reach the document — the body now starts a panel higher. Timestamp
values (`created`, any RFC3339 field) are shown formatted and edited raw;
`updated` reads relative, with the absolute time in its tooltip.

## Test plan
- [x] the body is replaced and the title re-derived — `actions::edit_body_replaces_the_body_and_rederives_the_title`
- [x] an edit that would introduce a verify problem is refused with nothing written — `actions::edit_body_that_breaks_verify_is_refused_and_writes_nothing`
- [x] set-field writes declared fields with the CLI value coercion and exposes declared_fields — `actions::set_field_writes_declared_fields_with_the_cli_value_coercion`
- [x] an undeclared key or out-of-set enum value is refused with nothing written — `actions::set_field_that_breaks_verify_is_refused_and_writes_nothing`
- [x] keys owned by a dedicated action are refused by name — `actions::set_field_refuses_keys_a_dedicated_action_owns`
- [x] remove-field removes, and a missing field is a named refusal — `actions::remove_field_removes_and_a_missing_field_is_named`
- [x] set-field without a value is a request error, not a removal — `action::tests::set_field_without_a_value_is_rejected_not_a_removal`
