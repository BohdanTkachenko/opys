# TUI bypasses write invariants: resurrection, ID race, rules-only saves

## Reproduction
Three holes, all from the TUI writing via `Project::save_doc` instead of the store: (1) pressing `e` on a doc in a terminal status (e.g. an archived feature) builds the status picker from non-terminal statuses with `.unwrap_or(0)` fallback, so Ctrl-S silently rewrites it to the first status and relocates it out of `_archived/`; (2) new-doc ids are allocated when the form opens and never re-checked at save, so a parallel `opys new` landing the same id gets clobbered by an unconditional `fs::write`; (3) saves validate with `rules::evaluate` only — deleting a required section and saving succeeds, leaving the corpus failing `verify`. Also: `--no-sync` is ignored and sync errors are discarded.

## Tasks
- [ ] make the current terminal status sticky/read-only in the edit form
- [ ] re-check id uniqueness (or re-allocate) at save time
- [ ] gate TUI saves on `verify::collect_problems`, like `query --write`
- [ ] honor `ctx.no_sync` and surface sync failures in the status line
