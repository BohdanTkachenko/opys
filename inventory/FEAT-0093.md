# Drag a card between columns to change its status

Kanban's native gesture: dragging a card onto another column issues the
existing `set-status` typed action — the same closed vocabulary, the same
write-time rules, nothing new server-side. The hovered column lights up; the
dragged card ghosts in place; the in-flight card dims until the reload
answers.

Refusals are the feature as much as the moves: dropping on a column whose
status a rule guards (a terminal status, `blocked` without a reason or
blocker, `implemented` without a checked test plan) shows the engine's message
verbatim above the board — the same message the CLI would print, often naming
the exact command that would satisfy the rule. The unset-status column is not
a drop target, because no action writes an empty status.

Columns are also height-bounded now: each column scrolls internally (scroll
shadows marking the cut-off edge) instead of one long column stretching the
whole page — which is what made showing every column tolerable again, and
turned the focus fold ([FEAT-0092 — Board focus mode folds settled columns](FEAT-0092.md)) into an opt-in.
Edge fades on the sideways scroll say when columns continue past the window,
and a card's timestamp reads relative (`3h ago`, the absolute in its tooltip)
on a minute ticker that also cools the heat ring between reloads.
