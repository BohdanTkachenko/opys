# engine: per-type transitions and the set-status guard

[ADR-0099 — Lifecycle is config: transitions, history, derived blocked, priority](ADR-0099.md) decisions 1 and 5.

Spec:

- `DocType` gains `transitions: BTreeMap<String, Vec<String>>`. Config
  validation: every key and target is a declared status; a terminal status has
  no outgoing edges; the initial status is a key when any transitions exist.
- `set_status::core` refuses an edge the map does not declare with
  `OpysError::Usage` naming the allowed targets (exit 2). A type without the
  map keeps any-to-any. `close` is unchanged (terminal is reached only there).
- Verify: when a type declares transitions, every consecutive history pair must
  be a declared edge; the first entry must be the initial status unless the
  document was imported (import is allowed to seed anywhere, and says so with
  the first key only).
- Remove `--status` from `new` (clap, `Action::New`, the skill, format.md).
  `import` keeps its status column.
- The node's `DocActions` bar already asks the API which statuses exist; it
  now gets the allowed targets for this document and shows only those.
