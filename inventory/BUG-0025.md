# YAML keyword-shaped strings silently change type on rewrite

## Reproduction
A doc with `spec: "True"` passes verify; any mutating command re-serializes it unquoted as `spec: True`, which re-parses as a boolean, and the next `verify` fails with "field 'spec' should be string". Same for `"0x1A"` (int) — `needs_quote` in `src/frontmatter.rs` covers only lowercase `true/false/null/yes/no` and Rust-parseable numbers, missing YAML 1.2 core-schema forms (`True/TRUE/Null/NULL`, hex, octal).

## Tasks
- [ ] extend `needs_quote` to the full YAML 1.2 core-schema scalar set (or round-trip-test the value through the parser to decide quoting)
- [ ] unit-test `True`, `NULL`, `0x1A`, `0o7` as string field values
