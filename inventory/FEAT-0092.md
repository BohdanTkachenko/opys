# Board focus mode folds settled columns

A kanban is for work in progress; a corpus accumulates `implemented` and
`archived` forever. **Focus mode** folds columns whose status names *settled*
work into a one-line strip under the grid ("settled, folded away:
implemented 12 · wontfix 3 · show"), with the count on the always-visible
toolbar toggle. The choice persists per corpus (localStorage); the strip and
the toggle each restore everything in one click.

Opt-in, not the default, since review: columns became height-bounded (each
scrolls internally — [FEAT-0093 — Drag a card between columns to change its status](FEAT-0093.md)), so showing every column no longer
costs a wall of page. The fold is for wanting settled work *out of sight*,
not out of the way.

What counts as settled is the status-tone engine's existing classification
(`statusSettled` in `lib/format.js`): the done family (done, implemented,
accepted, fixed, merged, shipped, …) and the retired family (wontfix,
superseded, archived, cancelled, …). A status the engine has never heard of is
never settled — an unfamiliar project vocabulary always stays visible, so
nothing silently disappears. No lifecycle is invented and nothing is added to
`opys.toml`: this is a view preference, not corpus semantics, in keeping with
"deliberately not a task board".

Two deliberate suspensions: a text search always looks through everything (the
grep reflex must never miss a settled document), and when every matching
document is settled the board shows an explicit "All settled" state rather
than an empty grid.
