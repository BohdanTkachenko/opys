# The document editor is our own block editor, published as svelte-blockdown

## Context

The document view edited a body by swapping the whole rendering for a
textarea of its markdown. Live testing wanted Obsidian's feel instead: the
rendered document is what you edit. Two more needs pull the same way: inline
comment threads ([ADR-0125 — Comment threads live in the document they discuss](ADR-0125.md)) need a toolbar over selected text that knows the
selection's *source* range, and document history ([FEAT-0124 — Document history and diffs in the web UI](FEAT-0124.md)) needs a diff that
reads like the document rather than like `git diff`.

Options weighed:

1. **A WYSIWYG editor** (ProseMirror, TipTap, Milkdown). It turns markdown into
   its own document model and serializes it back, so a one-word edit
   reformats the file: list markers, emphasis characters, escapes, and the
   `<!--comment-->` markers [ADR-0125 — Comment threads live in the document they discuss](ADR-0125.md) relies on are dropped or mangled.
2. **CodeMirror 6 live preview** (what Obsidian is). Faithful to the source,
   but about 300 kB minified on a ~200 kB bundle, and the UI's first runtime
   dependency besides Svelte.
3. **A character-level inline editor of our own** on `contenteditable`.
   Input methods, undo, caret mapping and paste are most of what CodeMirror
   is; a small one would be wrong in ways that corrupt files.
4. **A block-level editor of our own**: rendered blocks, one block at a time
   opened as source in place, with the source string as the only state.

## Decision

1. **Option 4.** The body is shown as rendered top-level blocks; a
   double-click opens one block as its markdown in a plain textarea in place;
   leaving it renders it again; leaving the document saves through
   `edit-body`, verify-gated as before. Edits splice the block's exact source
   range, so nothing the reader did not touch is rewritten.
2. **It is a separate, reusable package**: `svelte-blockdown`, in
   `packages/blockdown/`, Apache-2.0 like everything here ([ADR-0080 — Apache-2.0, permanently, for every crate in this workspace](ADR-0080.md)). It
   imports nothing from opys, ships no markdown renderer (the host passes
   `render`), and has no dependency beyond Svelte. The UI consumes it through
   `file:` exactly as an outside app would through npm. It can move to its
   own repository without changes.
3. **Rendering stays the node's.** Blocks are rendered by `POST /api/render`
   with the document view's comrak options, so a block mid-edit looks the
   same as the document. The endpoint is pure: no corpus, no path, bounded
   input.
4. **The package carries the diff and the selection toolbar** too
   (`BlockdownDiff`, the `toolbar` snippet), because both depend on the same
   block segmentation and source mapping.

## Consequences

- About 10 kB on the bundle instead of 300 kB; the bundle ceiling rises to
  224 kB.
- Inside an open block the reader sees that block's markdown, not inline
  rendering around the caret: the granularity is a paragraph or a list item,
  not a line.
- Each block is rendered alone, so reference-style link definitions and
  footnotes only resolve within their block. opys bodies do not use them.
- The segmenter is a second reading of CommonMark's block rules beside
  comrak. Where they disagree a block boundary can fall differently; the
  package's tests pin the cases that matter, and a disagreement costs a
  coarser block, not a changed byte.
- Checkboxes become clickable in the rendered body. A tick is a body edit,
  verify-gated, and is reverted on screen when refused.
- The Nix UI derivation is rooted at the repository so the `file:` link
  resolves in the sandbox; CI runs the package's tests.
