# Structured sections (mdprism schemas)

A section of kind `structured` declares its content shape as an mdprism schema in the config — headings, named lists, required fields — validated by `verify` and scaffolded by `new`. The default config ships a Manual-verification shape (Setup / Procedure / Expectations).

Partial because the module's `edit` and `render` halves have no production callers, and the `%strict` / `%frontmatter` directives are parsed and documented but not enforced by validation — the spec docs oversell what ships.

## Test plan
- [x] `new` scaffolds a structured section from the schema — `cli::new_scaffolds_structured_section_from_mdprism`
- [x] `verify` validates structured content against the schema — `cli::verify_checks_structured_section_against_mdprism`
- [x] strict ordering is respected by the validator — `mdprism::validate_respects_strict_ordering`
- [x] scaffold emits required nodes only — `mdprism::scaffold_emits_required_only`
- [ ] `%strict` rejects extra blocks as documented — uncovered (directive is currently a no-op)
- [ ] `edit` paths documented in the reference resolve — uncovered (documented syntax does not match the implementation)
