# Teams: node mesh, union view, per-seat plan

The team product ($/user/mo, [ADR-0053 — Everything open source; sell connectivity, hosting, and convenience](ADR-0053.md)) is not new storage — it is the same
server doing three more jobs over the same files ([ADR-0051 — Files and git are the only truth; the server is a view](ADR-0051.md)). The core insight:
a teammate's clone and an agent's worktree are the same object to the union
view, so the solo fleet dashboard *is* the team dashboard at a different
scale.

- **Node mesh**: every member's machine runs the node and registers to the
  team account (Connect per-seat — no new software). The web sees live state
  everywhere: "Dan's laptop is on TASK-0123, active 2m ago." Coverage, not
  compliance: git remains the correctness layer — a change from a nodeless
  machine (vim over ssh, web editor, CI) is exactly as visible as today,
  i.e. after push. The mesh only improves latency and completeness; there is
  no failure mode, so "register your machine" is an onboarding default, not
  a policed rule. Nodes broadcast *registry* state, not source code (the
  typed-API scope, [ADR-0052 — The hosted plane is blind and unprivileged](ADR-0052.md)), plus a per-node visibility toggle.
- **Union view**: main < pushed branches < live node overlays, always
  labeled, never resolved — git merge remains the only merger. Presents
  divergence and impending id collisions ([FEAT-0017 — renumber: cross-branch ID collision repair](FEAT-0017.md)'s territory) before the
  merge, which no per-corpus tool can show.
- **ID leases**: per [ADR-0055 — ID allocation: local lock, lease blocks in a ref, renumber as repair](ADR-0055.md) — blocks from the `opys/ids` ref, the team
  server as accelerating sub-lessor.
- **Bot committer**: the server commits + pushes registry-only changes
  (triage a bug, flip a status on main) as small auditable commits, so
  non-repo participants (PM, designer) act through the typed API with the
  server holding the repo credentials.
- **Escape hatch, documented not planned**: a database `Backend` impl if a
  team truly needs sub-second concurrent editing at scale — with the
  [ADR-0051 — Files and git are the only truth; the server is a view](ADR-0051.md) warning attached.

## Test plan
- [ ] a doc created on an unpushed branch of one member's node appears in every member's union view, branch-labeled
- [ ] two nodes with divergent uncommitted states of one doc render as two overlays; nothing merges them
- [ ] id collision between two branches is surfaced in the view before merge and repaired by the train
- [ ] bot committer: a status flip from the web lands as a registry-only commit on main and survives verify
- [ ] a nodeless contributor's pushed change integrates with no degradation beyond push latency

## Open questions
- **Write-path policy** (the one real open design question): ephemeral task
  docs ride their code branch and land with the PR; permanent-doc edits on
  main want the bot-committer fast path — per-doc-type default plus a
  team-level knob. Decide when building.
- Seat/identity model (who is a member vs a node vs an agent).
