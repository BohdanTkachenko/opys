# history: git status timeline

`opys history <id>` (opt-in `history` feature, gix-based) walks the repo history and prints the document's status timeline with commit hash, date, and author — following relocations across layout moves.

Partial because revisions are attributed to the newest commit while the content was current rather than the commit that introduced it, and the feature is undocumented in the README.

## Test plan
- [x] the status timeline renders with authors — `cli::history_shows_status_timeline_with_authors`
- [x] relocations are followed without leaking paths — `cli::history_follows_a_relocation_without_leaking_paths`
- [ ] each revision is attributed to the commit that introduced it — uncovered (known hole, see linked bug)
