# history: git status timeline

`opys history <id>` (the default-on `git` feature, gix-based) walks the repo history and prints the document's status timeline with commit hash, date, and author — following relocations across layout moves.

Both gaps that kept this partial are closed: a revision is attributed to the commit that *introduced* it (each commit's blob is compared against its first parent's), and the README's command overview documents `history` and `history --seed` while `format.md` documents the `[git]` table the reader takes its truth branch from. What is left is the first-parent walk itself — a status change that only ever existed on a merged side branch is attributed to the merge commit that brought it in, not to the commit on that branch — and a project that is not a git repository, where the command exits 2 rather than degrading to a notice the way the branch reader does.
