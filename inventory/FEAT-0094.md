# Priority ordering: drag a card within its column

Per [ADR-0095 — Priority is an opt-in declared field the board orders by](ADR-0095.md): a type that declares
`[fields.priority]` (`type = "int"`) gets ordered columns — ascending, lower =
higher, unprioritised cards last, id as the tiebreak. The top card is the one
an agent working a loop should take next.

Dragging a card to a new slot in its own column writes the priority its slot
implies, through the verify-gated `set-field` action: a midpoint between its
new neighbours in the common case (one write), a step of 10 past the end, and
a full renumber of the column (gap 10) only when the numbers leave no room or
the column has never been prioritised. An accent insertion line shows where
the card will land.

A prioritised card wears its rank — a small flag and the number after the id,
lower is higher — so a column's order can be read, not only inferred.
`DocSummary` carries `priority: Option<i64>` so the board orders without
opening documents. On a type that never declared the field, the first
reorder's refusal is the onboarding: verify's closed-frontmatter message names
the exact `opys.toml` block to add. This repo's own config declares it on
feature/task/bug/chore.
