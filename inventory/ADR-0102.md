# Branches are progress, main is truth

## Context

Agents work on branches, one per agent ([ADR-0050 — Retire the TUI; the web UI over the server is the human surface](ADR-0050.md)). A loop that hands work from
one agent to the next has to see what is in flight: that a task main still calls
`todo` is `in-progress` on one branch and `review` on another, and that ten
branches may hold the same task when competing models are set on one problem.

[ADR-0051 — Files and git are the only truth; the server is a view](ADR-0051.md) already says how divergence is shown: as labeled overlays in a union
view, never resolved by the server, with git as the only merger. The union
view does that today for *checked-out worktrees*, because the node has one
corpus actor per directory of files. A branch with no checkout has no directory,
so no actor, no watcher, no store; its documents exist only as git objects, and
the union cannot see it.

The engine can read git objects already. `opys history` walks the repository
in-process with gix, finds the id-named blob under the inventory base at any
commit, and decodes it through the real parser. It lives behind a feature that
is off by default, to keep gix out of the MSRV job; gix 0.84 declares 1.85,
under the 1.88 floor that `time` and comrak's builder macros set.

## Decision

1. **Main is the only truth for pickability and completion.** `next` evaluates
   status, blockers and priority on main. A blocker closed on a branch releases
   nothing until the merge lands. Nothing is finished until it is on main.

2. **Branches are progress.** opys reads the inventory at every bookmark or
   branch tip and at every worktree head, deduplicated by commit and labeled by
   bookmark when one points at the commit and by directory otherwise (the rule
   the union already uses, because jj-colocated worktrees detach HEAD). Each ref
   is diffed against main under the base and only the changed blobs are parsed,
   as full documents. The result is per-document *occupancy*: which refs hold
   it, in which status, since when. Remote refs are opt-in through a `branches`
   pattern list; keeping them fetched is the user's job. A commit-level walk,
   every commit not in main where a status differs, is the detailed view, on
   demand.

3. **The reader is in-binary and on by default.** gix, never a spawned git. The
   `history` feature becomes the default `git` feature; the branch reader, the
   history command and the migration seed share one module. A project that is
   not a git repository degrades to main-only rather than failing, the way the
   worktree scan already does when git is absent.

4. **Many branches on one document is legitimate.** opys reports occupancy; the
   orchestrator that spawns agents decides whether to pick an occupied item.
   Abandoned branches leave the picture through [ADR-0101 — Verify observes time: stuck, visits, `--fix`, and exit code 3](ADR-0101.md)'s TTL and can be
   harvested by a loop on the stuck status, because an abandoned attempt is not
   necessarily a wasted one.

5. **The node grows a ref reader per project**: a producer distinct from the
   corpus actors, triggered by ref changes, feeding additional columns into the
   union. The union function is pure over columns and takes them unchanged.

## Consequences

- gix enters the default build: the binary grows, the MSRV job compiles it, and
  every dependency bump is checked with the `msrv` devShell command. Today it
  fits; the pressure is upward only.
- Test fixtures need a detached-HEAD worktree to cover the jj case, which plain
  git can produce.
- `next` output carries occupancy and is JSON when asked, because orchestrators
  parse it.
- Two orchestrators on two machines double-pick until one fetches. Stated once
  in the docs; not solved here.
- [ADR-0051 — Files and git are the only truth; the server is a view](ADR-0051.md) is extended, not changed: overlays remain views, the merge remains
  git's. [ADR-0050 — Retire the TUI; the web UI over the server is the human surface](ADR-0050.md)'s "one project is N diverging corpora" gains the corpora that
  have no directory.
