# Worker pools: SSH fleet and managed swarm

Generalizes the orchestrator's worker seam beyond local worktrees: heavy
projects, many projects, or one-VM-per-worktree workloads scale out to a pool
of machines. Two drivers, matching [ADR-0053 — Everything open source; sell connectivity, hosting, and convenience](ADR-0053.md)'s split:

- **Static SSH pool (open source)**: "here are machines I already have" — a
  list of SSH hosts (homelab boxes, manually created VMs on any cloud). A
  worker is: connect, prepare environment, clone/branch, run the tool, push,
  report. Covers the self-hosting crowd completely with zero cloud API code
  and no opys infrastructure.
- **Managed swarm (Hosted tier)**: ephemeral workers provisioned on *our*
  substrate (the [FEAT-0060 — Hosted environments: managed development VMs](FEAT-0060.md) choice), metered per use. No BYO cloud accounts —
  that tier was cut deliberately ([ADR-0053 — Everything open source; sell connectivity, hosting, and convenience](ADR-0053.md)). Provisioning is one driver on
  one substrate, not a multi-cloud abstraction.

Cross-machine consistency needs nothing new: repo-is-the-database means a
worker is a clone on a branch; id collisions are the cross-branch case
[ADR-0055 — ID allocation: local lock, lease blocks in a ref, renumber as repair](ADR-0055.md) already covers (leases up front, `renumber` at merge); results land
through the [FEAT-0061 — Orchestrator: agents pick up registry work](FEAT-0061.md) merge train.

The hard parts, ranked by how often they kill products like this:

1. **Environment reproduction** on a fresh machine: detect `devcontainer.json`
   and Nix flakes, else run a user-supplied setup hook — never invent an
   environment format. Secrets are injected from the node, scoped and
   short-lived, never through the relay.
2. **Cost safety**: hard cap on concurrent workers, per-worker TTL, and a
   dead-man timer baked into the worker image so it self-destructs on idle
   *even if the head node dies*. Budget ("quota") is a first-class object —
   an orphaned VM quietly billing for a week destroys exactly the trust the
   model depends on.
3. **Driver surface**: a small trait — provision, destroy, list, boot
   payload — with the static pool and the one managed substrate as the only
   planned impls.

## Test plan
- [ ] a task runs end-to-end on a static-pool SSH host: env prepared, branch pushed, train merges it
- [ ] flake and devcontainer projects both reproduce their environment on a bare worker
- [ ] head-node kill test: orphaned managed workers self-destruct within their dead-man window
- [ ] budget object enforced: the pool never exceeds concurrent/spend caps under a full backlog
- [ ] secrets never transit the relay and expire with the worker

## Open questions
- Worker base image contents (git, agent CLIs preinstalled?) vs fully
  user-defined.
- Whether the static pool supports heterogeneous machines with per-host
  capability tags (e.g. gpu) in v1.
