# Hosted environments: managed development VMs

The **Hosted** tier (~$30/mo base + metered compute, [ADR-0053 — Everything open source; sell connectivity, hosting, and convenience](ADR-0053.md)) and the
mainstream entry door: web signup → a VM appears running the full opys node →
connect GitHub → work. No terminal required to start; SSH and a browser
terminal are available for those who want them (allowed here and only here —
the environment is ours to secure, [ADR-0052 — The hosted plane is blind and unprivileged](ADR-0052.md)). A Hosted customer runs the same
open-source binaries as a self-hoster and can eject with their data intact.

Design decisions already made:

- **One substrate**, our upstream account — compute is COGS (Cloudways
  precedent: managed resale on upstream providers). Candidates: Hetzner
  (margin: ~€8–14 VM under a $30 plan) or Fly Machines (per-second microVMs
  with a published per-user-dev-env blueprint; better fit for [FEAT-0062 — Worker pools: SSH fleet and managed swarm](FEAT-0062.md)
  bursts). Decide once, per-provider drivers are explicitly out ([ADR-0053 — Everything open source; sell connectivity, hosting, and convenience](ADR-0053.md) —
  no BYO cloud accounts).
- **Isolation**: VM per customer, never shared containers — the VM holds
  their GitHub credentials and model keys.
- **Abuse posture** (agents + rentable compute attracts miners): card
  required day one, CPU/egress caps, per-VM TTL and dead-man timers, hard
  concurrent-resource caps per account.
- **Metering**: base fee covers one bounded VM; everything beyond (bigger
  VM, [FEAT-0062 — Worker pools: SSH fleet and managed swarm](FEAT-0062.md) workers) is a metered line item at passthrough + margin.
- **Credential hygiene**: the user's agent credentials live on their VM for
  *their agents*; they are never routed into opys app features ([ADR-0054 — Bundle management-plane AI; execution-plane AI is bring-your-own](ADR-0054.md)).

## Test plan
- [ ] signup to working environment with zero local installs (the no-terminal path, timed)
- [ ] eject: a Hosted customer exports repo + inventory and comes up self-hosted with the same state
- [ ] runaway-cost drills: orphaned VM reaped by dead-man timer; account caps hold under a spawn loop
- [ ] isolation: no cross-customer network or disk path exists (pen-test the substrate config)
- [ ] metering matches substrate billing within tolerance on a month of synthetic load

## Open questions
- Substrate choice (Hetzner vs Fly) — decide with a spike measuring boot
  latency, volume persistence, and egress pricing under agent workloads.
- Region strategy v1 (single region is acceptable to start).
