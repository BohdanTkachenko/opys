# Parallel-agent write safety

The design claim is that writes go through the CLI so parallel agents do not collide — but today there is no lock: two concurrent `opys new` invocations can both read the same max id and allocate the same number. Planned: an advisory lock on the base dir held across load-to-flush, so concurrent invocations serialize instead of colliding; `renumber` remains the repair for cross-branch collisions the lock cannot see.

Now stage 0 of the platform staircase ([ADR-0055 — ID allocation: local lock, lease blocks in a ref, renumber as repair](ADR-0055.md)): the lock is the primitive
that makes both fleets of CLI agents and server-mediated actions ([FEAT-0058 — opys-server: the always-on node](FEAT-0058.md))
safe on one machine, and it blocks the orchestrator ([FEAT-0061 — Orchestrator: agents pick up registry work](FEAT-0061.md)). One design
requirement added by [ADR-0055 — ID allocation: local lock, lease blocks in a ref, renumber as repair](ADR-0055.md): id allocation goes behind a small seam
(trait) when the lock lands, so the team-scale lease-block source can slot in
later without rework — the lock covers same-machine, leases cover
cross-machine, `renumber` repairs the rest.

## Test plan
