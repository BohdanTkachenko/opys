# Parallel-agent write safety

The design claim is that writes go through the CLI so parallel agents do not
collide — made true by an exclusive advisory lock the storage backend holds
from load to flush. `MarkdownLocal` flocks a per-inventory file *outside the
repo* — under `$XDG_RUNTIME_DIR` (or the OS temp dir), named by the
canonicalized base path plus a hash, so the never-deleted lock file can't sit
untracked in the user's git status — before reading anything (so a concurrent
flush is never observed half-applied) and hands the guard to the store, which
carries it until the backend takes it back to keep it alive across the
post-plan filesystem writes. Contention is a retry (25 ms
polls) up to `OPYS_LOCK_TIMEOUT_MS` (default 10 s), then a clear exit-2 error.
Because the lock is a flock on an open handle, the OS releases it whenever the
process exits — error paths and kill -9 included — so stale locks cannot
exist. `renumber` remains the repair for cross-branch collisions the lock
cannot see.

Per [ADR-0055 — ID allocation: local lock, lease blocks in a ref, renumber as repair](ADR-0055.md), allocation sits behind the `ids::IdSource` seam:
`SequenceMax` (one past the corpus-wide max) is the default source used by
`new`/`import`/`query --write`; the team-scale lease-block source replaces it
without touching the commands. The lock covers same-machine, leases will cover
cross-machine, `renumber` repairs the rest.
