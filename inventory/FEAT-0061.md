# Orchestrator: agents pick up registry work

The autonomous loop, run from the node: you register work in the inventory;
the orchestrator selects ready documents, spawns your agent tool of choice on
each (`claude -p`, `codex exec`, …) in an isolated workspace (git worktree),
and shepherds results back. You stop saying "now let's work on this feature" —
registering the work *is* the instruction. Quota = concurrency. Differentiators
over vendor-locked loops: tool-neutral, invariant-enforced (the registry can't
go incoherent under parallel writers), self-hosted.

Design:

- **Pick policy is SQL** ([FEAT-0010 — SQL query surface](FEAT-0010.md)): the next-work query is configurable —
  default id order over `status = 'todo'` docs of ephemeral types with no
  blockers. This keeps priorities/assignees out of the core schema (the tool
  is deliberately not a task board): teams who want priority add a custom
  field and ORDER BY it in *their* policy.
- **Worker abstraction from day one**: "a place that can run a task" — local
  process in a worktree is impl #1; SSH host and managed VM ([FEAT-0062 — Worker pools: SSH fleet and managed swarm](FEAT-0062.md)) are
  later impls of the same trait. This single seam is what makes the swarm a
  driver addition instead of a rewrite.
- **Lifecycle**: claim (set in-progress under the [FEAT-0021 — Parallel-agent write safety](FEAT-0021.md) lock) → workspace
  (worktree + branch) → run tool with the doc as the work spec (test-plan
  sections are machine-checkable acceptance criteria) → on completion, PR +
  status per policy; on failure, release the claim with a log entry.
- **Integration queue**: the genuinely new hard part is N branches racing to
  land. A serialized merge train on the node: rebase → `renumber`
  ([FEAT-0017 — renumber: cross-branch ID collision repair](FEAT-0017.md)) → `verify` → merge, with human approval in front of it (from
  the web/phone UI). Every step is an existing primitive.
- **Execution-plane credentials are the user's own** ([ADR-0054 — Bundle management-plane AI; execution-plane AI is bring-your-own](ADR-0054.md)): the
  orchestrator runs *their* installed tools with *their* auth; it never
  supplies model access.

## Test plan
- [ ] two workers never claim the same doc (claim is atomic under the lock)
- [ ] a completed task lands through the merge train: rebase, renumber, verify, merge — corpus stays verify-clean
- [ ] a failed run releases the claim and records the failure in the doc's log section
- [ ] pick policy: a custom ORDER BY field changes selection order without core schema changes
- [ ] quota respected under a full backlog (N workers, no more)
- [ ] kill -9 mid-run leaves no stuck claim after the stale-claim sweep

## Open questions
- Claim representation (status alone vs a lease field with TTL) — must survive
  node crashes without human cleanup.
- Per-tool adapters: how much per-tool glue (prompt shape, completion
  detection) lives in config vs code.
