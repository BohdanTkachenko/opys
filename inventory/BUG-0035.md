# renumber misclassifies relocated docs and rewrites by raw substring

## Reproduction
Two defects: (1) `exists_at_base` probes the doc's *current* path against the merge-base tree, so a doc that existed at base but was relocated on the branch (e.g. archived) fails the probe and gets renumbered while the genuinely new doc keeps the number — the inverse of the contract. (2) `apply_renames` replaces raw substrings with no word boundary: once ids outgrow the pad width, renaming FEAT-1000 corrupts every FEAT-10005 mention, and rewrites happen inside code fences that linkify deliberately skips.

## Tasks
- [ ] resolve base existence by doc id (search the base tree for the id-named file), not current path
- [ ] use word-boundary-aware replacement for renames
- [ ] add integration coverage for the core keep/renumber resolution
