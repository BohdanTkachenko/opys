# Directional blockers

`opys block <id> --by <id>` records a directional relation on the same ID-to-title machinery as `references`: `blocked_by` on the blocked side, the inverse `blocks` on the blocker. That is the whole write — neither command touches `status`, and neither appends to `history`.

Blocked is *derived* from the relation, never stored ([ADR-0050 — Lifecycle is config: transitions, history, derived blocked, priority](ADR-0050.md) decision 3): a `blocked_by` entry is live while it is not struck through, still resolves to a document, and that document's status is not one its type declares in `releases_blocks`. A document is blocked exactly while it holds a live entry, so `unblock` unblocks by removing the entry rather than by restoring a status. `opys list --blocked` / `--unblocked` filter on it, and the board badge and the document view read the same function.
