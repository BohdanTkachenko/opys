# The generated systemd unit has no PATH, so worktree discovery silently dies

`opys web install` writes a unit with no `Environment=PATH=`, so the node
inherits the systemd *user manager's* environment. On a systemd-booted machine
that is not the login shell's `PATH` — here it is exactly one entry, systemd's
own `bin`:

```
$ systemctl --user show-environment | grep ^PATH
PATH=/nix/store/…-systemd-260.2/bin/
```

`git` is not on it. `discover::worktree_list` shells out to `git worktree list
--porcelain`, gets nothing, and `discover::group` reads an empty worktree list as
"not a repo, or no git" — the branch that exists for genuinely non-repo projects.
Every corpus then reports `branch: null`, `is_primary: true`, and the project's
other worktrees are invisible.

The failure is silent and looks like success. The dashboard comes up, the project
serves, verify is green — and the worktree union view, which is one of
[FEAT-0058 — opys-server: the always-on node](FEAT-0058.md)'s headline features, is quietly missing with nothing anywhere
saying so. Nobody notices until they go looking for a worktree they know exists.

It reproduces on this repo's own inventory, which is how it was found: a running
node served `/home/dan/Projects/opys` as a single corpus with `branch: null`
while `git worktree list` showed two worktrees, both carrying `opys.toml`, and a
restart did not change it.

Two things are worth separating in the fix. The unit should carry a `PATH` that
can actually find `git`. And `group` should not read "the git call produced
nothing" as "this is not a git repository" — a repo whose `git` is missing is a
different condition from a directory that was never a repo, and the node should
say the former out loud rather than degrading into the latter.

## Reproduction

1. `opys web add <a project inside a git repo that has a second worktree>`
2. `opys web install` and start the unit under `systemctl --user`.
3. `curl localhost:6797/api/projects`

The project reports one corpus with `branch: null`, and the sibling worktree is
absent. Running `opys web start` from a shell instead serves both. Observed on
0.12.0.

## Tasks
- [x] give the generated unit a `PATH` that resolves `git` (or find git at build/run time and stop shelling out through `PATH`)
- [x] distinguish "git unavailable" from "not a repository" in `discover::group`
- [x] surface the former in the API and the dashboard rather than degrading silently
- [x] a test that a repo with worktrees does not collapse to a single corpus when `git` cannot be found
- [x] full CI gate green

## Progress
- 2026-08-29: found while checking whether a newly created worktree of this repo
  showed up in the running node's union view. It did not, and a restart did not
  help; `systemctl --user show-environment` explained why.
- 2026-08-29: fixed, both halves. `unit_text` takes a `path_env` and `install`
  passes the PATH it ran under — the one shell where `opys` and `git` both
  demonstrably work — while the function stays pure. And `git()` now returns
  `Result<_, GitFail>` separating `Unavailable` from `Failed`, so `group` marks
  every corpus of a project whose worktrees could not be read instead of
  silently presenting it as a lone directory.
