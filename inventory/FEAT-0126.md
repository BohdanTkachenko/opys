# Inline comment threads: a human-agent review loop

Select a passage in the document view, leave a comment, and the next agent that
works in the repository finds it with `opys comments list --unresolved
--turn=agent`, replies or fixes the passage, and resolves the thread — which the
human then sees in the dashboard. The storage decision is [ADR-0125 — Comment threads live in the document they discuss](ADR-0125.md): threads live
in a reserved `## Comments` section of the document itself.

## Behaviour

- **Web.** Selecting text in a rendered section offers *Comment*; the thread is
  drawn in a margin beside its anchor (stacked under the document on a narrow
  screen), with reply, resolve and reopen. Outdated threads collect at the end of
  their section. The board card shows an open-thread badge, split by whose turn
  it is; the omnibox can filter to "waiting on me". Writes are new typed actions,
  so the node still cannot run anything else.
- **CLI.**
  - `opys comment add <id> --section <heading> --quote <text> --body <text>`
  - `opys comment reply <id> <thread> --body <text>`
  - `opys comment resolve|reopen <id> <thread>`
  - `opys comments list [<id>…] [--unresolved] [--turn=agent|human] [--json]`
    prints each thread with its anchor and the passage as it stands now, so an
    agent can act without opening the file.
  - `--as agent|human` sets the author kind; the default comes from
    `OPYS_AUTHOR_KIND` (agent harnesses set it), else `human`. The author name
    is git's `user.name`.
- **Agent rule.** `skills/opys/agent-rule.md` gains the one-line loop: check
  the agent's turn before starting, and leave a reply on every thread touched.
- **Format.** format.md specifies the section grammar; `verify` validates it.

## Test plan

- [ ] `comment add` writes a thread with a stable id, anchor, `open` state and a human entry
- [ ] `comments list --turn=agent` lists a thread whose last entry is human and not one whose last entry is an agent's
- [ ] a reply by an agent flips the thread to the human's turn
- [ ] `resolve` hides the thread from `--unresolved`; `reopen` restores it
- [ ] editing away the quoted passage makes the thread outdated in `comments list`, without a verify failure
- [ ] `verify` rejects a duplicate thread id and an unknown state
- [ ] the comments section is excluded from the `blocks` projection and from title/section extraction
- [ ] the node's comment actions refuse a document type without `comments = true`
- [ ] `close` on a document with open threads names them
