# Inline comment threads: a human-agent review loop

Select a passage in the document view, leave a comment, and the next agent that
works in the repository finds it with `opys comments list --unresolved
--turn=agent`, replies or fixes the passage, and resolves the thread, which the
human then sees in the dashboard. Agents open threads the same way, to ask the
human something about a specific passage. The format is [ADR-0125 — Comment threads live in the document they discuss](ADR-0125.md): marker pairs
around the anchored text, threads in a reserved `## Comments` section.

## Behaviour

### CLI

Every comment write goes through these; nothing else edits markers or threads.

- `opys comment add <id> <section> <text> --body <md>` opens a thread anchored
  to `<text>` inside `<section>` (`"## Test plan"` or `"Test plan"`), wrapping
  it in a marker pair. With no `<section>`/`<text>` the thread is
  document-level. `--body -` reads the entry from stdin.
- The search for `<text>` is exact within the section, ignoring differences in
  whitespace and line breaks, and must find **exactly one** match. When it finds
  several, the command fails and lists each candidate with its file line number
  and some context, and these narrow it down:
  - `--line N`: the match that starts on line N of the file; `--line ~N`: the
    match nearest line N (still an error on a tie).
  - `--after <s>`: the match must be preceded by `<s>` (only whitespace or
    markdown punctuation between them).
  - `--before <s>`: the match must be followed by `<s>`, likewise.
  - They combine; any combination that leaves zero or several matches fails
    with the candidates listed again. No match at all fails and says which
    section was searched.
- A match that would open or close inside a code span or fence is refused,
  suggesting the enclosing block.
- `opys comment reply <id> <thread> --body <md>` appends an entry.
- `opys comment resolve <id> <thread> [--body <md>]` resolves, optionally
  with a closing entry, and removes the markers; `reopen` restores them when
  the recorded text is still found once in its section, and otherwise reopens
  the thread as document-level and says so.
- `opys comments list [<id>…] [--unresolved] [--turn=agent|human] [--json]`
  prints each thread with its section, the anchored text as it stands now,
  the file line, and the entries, so an agent can act without opening the
  file. Without ids it covers the whole inventory.
- `opys comments prune [<id>…] --resolved` drops resolved threads.
- `--as agent|human` sets the author kind; the default comes from
  `OPYS_AUTHOR_KIND` (agent harnesses set it), else `human`. The author name is
  `--author`, else git's `user.name`.

### Enforcement

`verify` runs the [ADR-0125 — Comment threads live in the document they discuss](ADR-0125.md) checks on every document of a type with
`comments = true`, so a hand edit that drops, duplicates or moves a marker
fails the gate. Markers and the comments section are stripped before title and
section extraction, projections, section checks and mdprism.

### Web

Anchored text is highlighted; the thread is drawn in a margin beside it
(stacked under the document on a narrow screen), with reply, resolve and
reopen. Selecting text offers *Comment*, which calls the same code as `comment
add` with the selection's exact offsets, so the web never needs the narrowing
flags. The board card shows an open-thread badge split by whose turn it is; the
omnibox can filter to "waiting on me". Writes are new typed actions, so the
node still cannot run anything else.

### Agent rule

`skills/opys/agent-rule.md` gains the loop: check `comments list --unresolved
--turn=agent` before starting, reply on every thread touched, never edit a
`<!--comment …-->` marker by hand.

## Test plan

- [ ] `comment add` wraps the unique match in a marker pair and writes a thread with a fresh id, the quote, `open` and a human entry
- [ ] an ambiguous `<text>` fails listing every candidate with its line; `--line`, `--line ~N`, `--after` and `--before` each pick one
- [ ] a narrowing that leaves zero or several candidates fails with the candidates listed
- [ ] a match inside a code span or fence is refused
- [ ] markers may span lines and overlap another thread's markers
- [ ] `comments list --turn=agent` lists a thread whose last entry is human and not one whose last entry is an agent's
- [ ] an agent reply flips the thread to the human's turn
- [ ] `resolve` removes the markers and hides the thread from `--unresolved`; `reopen` restores the markers, or reopens document-level when the text is gone
- [ ] `verify` fails on a missing, unpaired, duplicated, cross-section, in-code or empty marker pair; an orphan marker; markers on a resolved thread; a duplicate id; an unknown state
- [ ] ids are never reused after `prune`
- [ ] markers and the comments section do not appear in titles, `sections`/`blocks`, section checks or mdprism validation
- [ ] the node's comment actions refuse a type without `comments = true`
- [ ] `close` on a document with open threads names them
