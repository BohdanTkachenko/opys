# Apache for what runs on your machine; copyleft for the scaling layer

## Context

[ADR-0056 — License split: Apache-2.0 core, AGPL server components](ADR-0056.md) drew the license line around "server-side components": the CLI, engine
and backends Apache-2.0, and the server, relay, and hosted web AGPL-3.0.
Building the first of those components (TASK-0067, landed as an AGPL crate)
showed the line is in the wrong place.

The always-on node is not the thing being sold. It is the local tool — the
replacement for the retired TUI ([ADR-0050 — Retire the TUI; the web UI over the server is the human surface](ADR-0050.md)), the thing a solo user runs on their
own laptop over their own files, and the free tier [ADR-0053 — Everything open source; sell connectivity, hosting, and convenience](ADR-0053.md) promises ("run opys
on your laptop, get a localhost URL"). Copyleft there taxes exactly the people
self-hosting while protecting nothing a competitor actually needs: rehosting a
localhost daemon is not a business. What *is* the business is the layer that
turns local nodes into a fleet — the relay, the hosted control plane, the
managed pools.

The cost showed up immediately in the UI story. With the TUI gone, the obvious
front door is `opys web start`, which requires the Apache CLI to link the node
crate — precisely what [ADR-0056 — License split: Apache-2.0 core, AGPL server components](ADR-0056.md) forbids. A git-style dispatch to a sibling
binary works around the linkage, but it puts a second install step in front of
the primary human surface.

## Decision

The boundary is **what runs on your machine** versus **what makes it scale and
sell**.

Everything a user runs locally over their own files is Apache-2.0: `opys` (the
CLI), `opys-engine`, the storage backends, and `opys-server` — the always-on
node and its embedded web UI included. The layer that turns nodes into a fleet
or a service is copyleft: the relay ([FEAT-0059 — Relay and Connect: remote access to your nodes](FEAT-0059.md)), the hosted control plane, and
the orchestration/teams components sold as a service ([FEAT-0061 — Orchestrator: agents pick up registry work](FEAT-0061.md), [FEAT-0063 — Teams: node mesh, union view, per-seat plan](FEAT-0063.md)), each
decided in its own ADR before its first release. AGPL-3.0 remains the
presumptive copyleft choice; nothing here forecloses another if the relay's
economics argue for it.

[ADR-0056 — License split: Apache-2.0 core, AGPL server components](ADR-0056.md) is superseded. `opys-server` relicenses to Apache-2.0 now, before it
has a single outside contributor — the same "decide at birth" reasoning [ADR-0056 — License split: Apache-2.0 core, AGPL server components](ADR-0056.md)
itself used, so no CLA question arises.

Because both sides are Apache, the CLI may depend on the node crate, and the web
UI's entry point becomes an `opys` subcommand rather than a separate binary
([ADR-0077 — The node serves an explicit allowlist; discovery only suggests](ADR-0077.md)).

## Consequences

- The moat is the relay and the hosted plane, not the tool. This is what
  [ADR-0053 — Everything open source; sell connectivity, hosting, and convenience](ADR-0053.md) already said the business was; the license now matches it, and the
  free tier is entirely permissive.
- A competitor can rehost the node without publishing changes. Accepted: the
  node alone is not the product, and the moment they add multi-node access they
  are in the relay's copyleft.
- Corporate users who refuse copyleft on anything they run internally are
  unblocked completely rather than partially. That was [ADR-0056 — License split: Apache-2.0 core, AGPL server components](ADR-0056.md)'s own stated
  worry, and it applied to the node as much as to the CLI.
- The relay's license must be settled before [FEAT-0059 — Relay and Connect: remote access to your nodes](FEAT-0059.md)'s first release, on the
  same "decide at birth" logic. It is the one place where the choice is load
  bearing.
- Cleanup carried by the [FEAT-0058 — opys-server: the always-on node](FEAT-0058.md) chain: the crate's `license` field, its
  README, AGENTS.md/CLAUDE.md, and the root README revert to Apache-2.0, and the
  AGPL text at `opys-server/LICENSE` is deleted — the root Apache LICENSE covers
  the workspace, as it does for the other member crates. TASK-0067 shipped the
  crate as AGPL and is already closed, so this ADR is the record of that
  reversal.
