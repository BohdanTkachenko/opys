# Bulk ID lists and stdin piping

Every id-taking mutating command (`set-status`, `tag`, `retire`, `block`, `unblock`, `close`) takes an id list three interchangeable ways: several positionals (`opys set-status FEAT-1 FEAT-2 partial`), a comma-separated list, or `-` to read ids from stdin — so `opys list --type task --status in-progress --format ids | opys close -` composes. Repeated ids are collapsed, keeping first-seen order. A batch is all-or-nothing: ids are applied in order against one loaded corpus and the first failure aborts the whole invocation with exit 2, writing nothing — a widened list that hits a bad id cannot land half a change. Options may lead the ids or trail them. In the other direction of the pipe, a producer whose reader goes away (`opys list --format ids | head -1`) stops quietly at exit 0: no command turns a closed pipe into a crash.
