# TUI: cut the built-in editor, spawn $EDITOR instead

Decision: the framework (ratatui) is not the problem — the built-in editor is. Roughly 60% of the TUI code (form ~575 lines, hand-rolled textarea ~307, markdown renderer ~527) exists to edit documents inline, and that is exactly where all three invariant-bypass holes live ([BUG-0031 — TUI bypasses write invariants: resurrection, ID race, rules-only saves](BUG-0031.md)). A read-mostly board is smaller, safer, and easier to polish.

## Tasks
- [x] make the board read-mostly: filter, sort, view, status changes routed through the real command cores
- [x] `e` spawns $EDITOR on the document file; run the sync/verify pass on return and surface problems in the status line
- [x] delete the form/textarea editing path (fallback option if inline editing must stay: replace the hand-rolled textarea with the tui-textarea crate and gate saves on verify::collect_problems)
- [ ] add a screenshot/GIF of the slimmed board to the README

## Progress
- Decided during the pre-announcement review discussion.
- Cut `form.rs`, `textarea.rs`, `save.rs`; the board is now read-mostly. Status changes go through `set_status::core` (picker offers only non-terminal statuses), close through `close::core`, and `e`/`Enter` opens the doc in `$EDITOR` then runs the auto-sync + verify pass. The input thread was replaced with an inline poll so the spawned editor owns stdin. In-TUI doc creation was dropped in favour of `opys new`. This closes the [BUG-0031 — TUI bypasses write invariants: resurrection, ID race, rules-only saves](BUG-0031.md) invariant-bypass holes.
