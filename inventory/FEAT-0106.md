# `opys next`: the pick oracle

The question every loop asks first is "what should I work on". `opys next`
answers it from the inventory, with no server and no runner: the top items of a
status, ordered by the type's chain, minus everything blocked, plus what the
branches say about each one.

There is deliberately no claim. An orchestrator spawns agents and decides
whether an item that is already in progress on some branch is taken or is fair
game for a competing attempt. opys reports; the orchestrator chooses. That is
also why the output is JSON when asked: it is parsed, not read.

## Behaviour

- `opys next --status <s> [--type <t>] [-n N] [--json]` lists the first N
  documents at that status, ordered by their type's `order_by` chain with
  effective priority ([FEAT-0104 — Configured lifecycle: transitions, history, derived blocked, priority](FEAT-0104.md)), excluding blocked ones.
- Pickability is evaluated on **main's** inventory, the corpus the command runs
  in. A blocker closed on a branch does not release anything ([ADR-0102 — Branches are progress, main is truth](ADR-0102.md)).
- A document whose `requires_link` target is at a status in that type's
  `releases_blocks` set, such as a task under a `wontfix` feature, is not
  pickable and is listed under a separate `orphaned` key.
- Each item carries **occupancy**: the refs that hold it in a different status
  than main, with that status and the last history key ([FEAT-0107 — Branch reader: the in-binary git adapter](FEAT-0107.md)). Stuck
  occupants are flagged with the [ADR-0101 — Verify observes time: stuck, visits, `--fix`, and exit code 3](ADR-0101.md) predicate. `--exclude-occupied` drops
  items with any live occupant, for the one-agent-per-node case.
- `--limit-from-config` reads N from `[types.X.limits]`, the per-status cap the
  flow view draws, so a loop and the view agree on the node's size.
- The selection is an engine function, `next::pick`, called by the CLI and by
  the node's endpoint, so the two cannot drift.

## Test plan
- [ ] `next` lists unblocked documents at a status in `order_by` order and stops at N
- [ ] a document blocked by a live blocker is excluded, and included once the blocker closes on main
- [ ] a task whose only linked feature is `wontfix` is reported as orphaned, not picked
- [ ] occupancy shows a branch holding the item at another status, and `--exclude-occupied` drops it
- [ ] a stuck occupant is flagged with the same result the verify predicate gives
- [ ] `--json` output is stable and documented; the human output is a table
- [ ] with no git repository the command works main-only and says so once
