# opys-server: project discovery and the corpus registry

Discovery turns the `run` command's roots into the server's data model. Two
types in a new `opys-server/src/discover.rs`:

```
Corpus { cid: String,            // stable id: sanitized canonical root + fnv64 hash,
                                 // same recipe as the backend's lock_path naming
         root: PathBuf,          // dir containing opys.toml (canonicalized)
         base: PathBuf,          // root joined with the config's base
         group: String,          // project-group key (see below)
         branch: Option<String>, // git branch checked out here, if a repo
         is_primary: bool }      // the main worktree of its group
ProjectGroup { key: String, name: String, corpora: Vec<Corpus> }
```

Rules (all decided; implement exactly):

- Scan each root recursively for `opys.toml` files. Skip directories named
  `.git`, `target`, `node_modules`, `.direnv`, and hidden dirs (`.` prefix).
  Every hit's directory is a corpus root. Parse the config with
  `opys_engine::project_config::ProjectConfig::load` to resolve `base`; a root
  whose config fails to parse is kept with an `error` note (the API will show
  it) rather than dropped silently.
- Worktrees: for each corpus root, run `git -C <root> rev-parse
  --git-common-dir` (tolerate failure = not a repo). Roots sharing a
  canonicalized common dir form one `ProjectGroup`; additionally run `git -C
  <root> worktree list --porcelain` once per group and include any listed
  worktree that contains `opys.toml` at the same relative path as the group's
  primary, even if it lies outside the scanned roots. The first entry of
  `worktree list` is the main worktree → `is_primary`. Branch comes from the
  porcelain output. Non-repo corpora form single-corpus groups keyed by their
  own path.
- Group `name` = last path component of the primary root. Group `key` = same
  hash recipe as `cid` over the common dir (or the root for non-repos).
- Shelling `git` is allowed here (the engine's `renumber` already shells git);
  every git call must tolerate absence of git or of a repo by degrading to a
  single-corpus group. Never fail discovery because git failed.
- Pure logic (grouping, keying) goes in free functions unit-tested without
  git; the git-dependent path gets integration-style tests that create real
  repos with `git init` + `git worktree add` in a tempdir (skip the test with
  an explicit message if `git` is not on PATH).
