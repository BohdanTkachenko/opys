# close does not reserve an unreferenced doc's id

## Reproduction
In a fresh project: `opys new --type task --title A --features FEAT-0001`, remove the feature link, or simply `opys new` a task nobody references, then `opys close TASK-000N --force` and `opys new --type task` again — the new doc is issued the same id. Close reserves ids only via struck tombstones in other docs' relation maps; with no inbound reference there is no tombstone and no ledger entry, contradicting the never-reuse invariant (and `cleanup` reopens the same hole by stripping tombstones). The machinery exists — `query --write` DELETE writes the ledger for unreferenced docs (`src/store/`, test `query_write_delete_unreferenced_reserves_id`); close should do the same.

## Tasks
- [ ] make `close` (and `cleanup` when it strips the last tombstone) write the retired ledger for otherwise-unreserved ids
- [ ] add an integration test closing an unreferenced doc and asserting the id is not reissued
