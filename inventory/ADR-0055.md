# ID allocation: local lock, lease blocks in a ref, renumber as repair

## Context

Ids are a single global monotonic sequence ([FEAT-0002 — Global never-reuse ID sequence and retired ledger](FEAT-0002.md)). Today's design covers
two scales: same-machine races get the planned advisory lock ([FEAT-0021 — Parallel-agent write safety](FEAT-0021.md)), and
cross-branch collisions get repaired by `renumber` ([FEAT-0017 — renumber: cross-branch ID collision repair](FEAT-0017.md)) at merge.
Team scale breaks the second half as a *product*: with several humans plus
agent fleets branching constantly, collisions become routine, and an id that
can change at merge stops being a stable communication handle ("as discussed
in TASK-0123" must never mean a different doc next week). A central allocation
service was wontfixed ([FEAT-0043 — Centralized global ID allocation](FEAT-0043.md)) to preserve "no host, works offline,
repo-is-the-database" — any team mechanism must keep that true.

## Decision

Three layers, each a fallback for the next:

1. **Advisory lock** ([FEAT-0021 — Parallel-agent write safety](FEAT-0021.md)) serializes same-machine invocations, held
   load-to-flush. Allocation goes behind a small trait when this lands, so the
   layers below slot in without rework.
2. **Lease blocks in an orphan ref** (e.g. `opys/ids`): a ledger of granted id
   blocks living in the repo itself, out of every working tree. Taking a lease
   is commit + push; git's per-ref push atomicity is the compare-and-swap —
   concurrent claimants get a non-fast-forward rejection and retry with the
   next block. Blocks are sized by consumer (≈10 for a human's node, ≈100 for
   a fleet node) so the push round-trip is rare. Works with nothing but the
   repo — no opys infrastructure — so it is an open-source-core capability
   — no infrastructure, so it belongs in the core. A coordinating server could
   later accelerate it by holding a pre-claimed block and sub-leasing instantly,
   refilling via the ref; the ref would remain truth and the server a cache ([ADR-0051 — Files and git are the only truth; the server is a view](ADR-0051.md)).
3. **`renumber` remains the repair of last resort** for offline/forked work
   that allocated without a lease.

Unused lease blocks leave gaps in the sequence. Gaps are harmless and expected:
the invariant is monotonicity and never-reuse, not density. Do not "fix" them.

## Consequences

- [FEAT-0043 — Centralized global ID allocation](FEAT-0043.md) stays wontfixed on its own terms: this is still not a central
  allocator — the repo allocates from itself, and everything works offline.
- `verify`/`max_doc_id` semantics are untouched (leases only extend the
  sequence upward); the lease ledger is read by allocation, not by verify.
- Needs a pushable non-standard ref; org branch-protection policies may need a
  carve-out — document it.
- Prior art for refs-as-coordination-state: Gerrit's `refs/meta/*`.
