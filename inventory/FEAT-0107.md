# Branch reader: the in-binary git adapter

The engine reads the inventory as it exists on every branch and worktree head,
in-process through gix, never by spawning git. It generalizes what `opys
history` already does, finding the id-named blob under the base at a commit,
and it powers three things: occupancy for `next`, columns for the union and the
flow view, and an accurate seed for history migration.

The feature that was `history`, off by default, becomes `git`, on by default
([ADR-0102 — Branches are progress, main is truth](ADR-0102.md)). A build without it, or a project that is not a repository, leaves the
*reader* main-only and saying so; nothing in the reader fails. The `history`
command is the one thing with no main-only answer to give — it reports the
committed timeline and nothing else — so in either case it names what is
missing and exits 2 rather than printing a history it never looked for.

## Behaviour

- `refs::occupancy(project)` returns, per document, the set of refs that hold
  it at a status different from main, with status and last history key. Refs
  are every local bookmark or branch tip plus every worktree head, deduplicated
  by commit and labeled by bookmark when one points at the commit and by
  worktree directory otherwise. `[git] branches = ["refs/heads/*"]` widens or
  narrows the set; remotes are opt-in.
- Each ref is diffed against main under the inventory base; only changed blobs
  are decoded, through the real parser, as full documents. Unchanged documents
  are main's and are not re-read.
- `opys history <id>` is unchanged in output and now always available. The
  subcommand is parsed in every build; a binary without the `git` feature
  answers it by naming the feature (exit 2), never with clap's "unrecognized
  subcommand".
- `opys history --seed` writes a `history` map for a document from its git
  timeline, for the one-off migration. It refuses to overwrite an existing map.
- The reader is a module in the engine with no filesystem writes; the node's
  ref reader ([TASK-0119 — opys-server: ref reader, occupancy in the union, `next` endpoint, autofix](TASK-0119.md)) is a caller, not a copy.

## Test plan
- [x] a document changed on a branch with no worktree appears in occupancy with that branch's status — `git::tests::a_branch_with_no_worktree_appears_in_occupancy_at_its_status`
- [x] a detached worktree head on the same commit as a bookmark is one column, labeled by the bookmark — `git::tests::a_detached_worktree_head_on_a_branch_commit_is_one_column_named_for_the_branch`, `git::tests::a_symbolic_worktree_head_resolves_like_a_branch`
- [x] two worktrees on one commit and no bookmark are labeled by directory — `git::tests::two_worktrees_on_one_commit_and_no_branch_are_labeled_by_directory`
- [x] a remote ref is ignored by default and included when the pattern list names it — `git::tests::a_remote_ref_is_ignored_until_the_branches_patterns_name_it`
- [x] an unchanged document is not decoded (counted by a test double on the blob reader) — `git::tests::an_unchanged_document_is_never_decoded`
- [x] a non-repository project yields empty occupancy and a single notice — `git::tests::a_non_repository_yields_empty_occupancy_and_a_single_notice`; the command over it says so and exits 2 — `cli::history_outside_a_repository_says_there_is_none_and_exits_2`, `cli::history_without_the_git_feature_names_the_missing_feature`
- [x] `history --seed` reproduces the status timeline as a history map and refuses to overwrite — `cli::history_seed_writes_the_lifecycle_map_from_the_git_timeline`, `cli::history_seed_refuses_to_overwrite_an_existing_map`, `cli::history_seed_records_an_uncommitted_status_last`
- [ ] the `msrv` build passes with the `git` feature on (a CI/gate fact, not a test: `msrv` passed on rustc 1.88.0 — see [TASK-0117 — engine: the gix branch reader, default-on, and the comrak trim](TASK-0117.md)'s Progress)
