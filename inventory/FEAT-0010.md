# SQL query surface

Per invocation the corpus is decomposed into an in-memory GlueSQL database; `opys query "SELECT …"` exposes it read-only. Every statement is plan-guarded to SELECT — a compound that smuggles in DML is rejected before anything executes — and the command never flushes, so no query can change a file. All tables are queryable: the authoritative `docs`/`tags`/`relations`/`fm_fields`/`retired` and the derived `fields`/`sections`/`blocks` projections, the last decomposing each body into its `##` sections. `-` reads the SQL from stdin and `--stdin` binds stdin to `$1`. Writes are lifecycle commands ([ADR-0100 — SQL is read-only; every write is a lifecycle command](ADR-0100.md)): a bulk edit pipes `opys list --format ids` into one.
