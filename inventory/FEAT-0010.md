# SQL query surface

Per invocation the corpus is decomposed into an in-memory GlueSQL database; `opys query "SELECT …"` exposes it read-only (plan-guarded to SELECT), and `--write` allows INSERT/UPDATE/DELETE that are applied only if the post-write corpus still passes the full `verify` check set — otherwise nothing is flushed. The writable `blocks` projection splices section edits back into bodies byte-accurately.
