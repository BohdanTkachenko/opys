# Remote MCP: manage the registry from shell-less hosts

Originally wontfixed: "skill + CLI is the interface — every coding agent has a
shell; revisit if non-shell hosts (claude.ai chat, ChatGPT connectors) show
real demand." That revisit clause has fired: managing a registry from Claude Web
or a phone is a real use case, and those hosts have no shell.

Scope — deliberately *not* a CLI mirror: a remote MCP endpoint exposed through
the node, speaking the same typed opys API as every other client
(registry reads, queries, command-core actions; no shell, ever).
Tools are the human-lite management set: list/query/read docs, create work
items, set status, tag, block, close. Coding agents keep the skill + CLI —
this surface exists for management from environments that cannot run a
process, which is why it does not reopen the original wontfix reasoning for
the agent path.

Architecture: the MCP server terminates at the node (per-node endpoint,
OAuth) — one more client protocol on the same API, not a second integration
surface to keep in sync.

## Test plan
- [ ] a claude.ai connector can list, query, create, and set-status against a node end to end
- [ ] MCP actions run the same command cores + rules as the CLI (an invalid transition is rejected identically)
- [ ] the MCP surface cannot reach anything outside the typed API (no shell, no file paths)
- [ ] revoking a client's OAuth grant ends its access
