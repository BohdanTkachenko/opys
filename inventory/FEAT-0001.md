# Config-driven document types

One `opys.toml` at the project root declares every document type: its ID prefix, statuses, custom frontmatter fields, required sections, and validation rules. There is no hardcoded type set — a document's type is its ID prefix, and the whole tool (create, verify, query) works for any `[types.<name>]` block a project adds. `opys config validate` self-checks the config.
