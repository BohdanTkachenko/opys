# The web UI may manage the allowlist within $HOME

## Context

[ADR-0077 — The node serves an explicit allowlist; discovery only suggests](ADR-0077.md) decided two things at once and justified only one of them.

The justified half is that **no endpoint accepts a filesystem path**. That rule
is load-bearing, and more so than its own ADR argued. Until [BUG-0084 — A project's inventory base can escape its root](BUG-0084.md) was fixed a
project's `base` could escape its root, so an endpoint taking a caller-supplied
path was not merely a way to read someone's inventory — it let a caller aim the
node at a directory whose config redirected reads and writes anywhere on the
filesystem, with the node's own privileges. The escape is closed now; the rule it
argues for is not, because the next such config field would reopen it.

The unjustified half is that **the allowlist is editable only by hand, on disk**.
That was never argued for separately; it fell out of the first rule because
"allowlist a project" was assumed to mean "name its path". The cost is a product
seam: the node is a long-lived service on a homelab or VPS, its interface is a
web dashboard, and adding a project to it requires an SSH session. A user who
reached the dashboard through a browser has to leave the product to do the one
thing the product is for. [FEAT-0042 — Remote MCP: manage the registry from shell-less hosts](FEAT-0042.md) already exists because of this friction,
but it routes the fix to a separate MCP surface and leaves the dashboard unable
to manage what it displays.

The two halves are separable. The security property is about *what a caller can
name*, not about *which client does the naming*.

## Decision

The web UI may manage the allowlist, bounded by rules the node enforces itself.

1. **`$HOME` is the boundary.** A path configured through the UI must, after
   canonicalization, be under the canonicalized `$HOME`. Canonicalizing first is
   the whole point: it resolves `..` and symlinks, so a link inside `$HOME`
   pointing out of it fails the check rather than passing on its spelling.
2. **No dot-components.** No component of the canonicalized path may begin with
   `.`, which puts `~/.ssh`, `~/.config`, `~/.gnupg` and friends out of reach.
   The predicate already exists as `discover::is_skipped` and is reused rather
   than reimplemented, so the scan and the UI cannot drift apart on what
   "hidden" means.
3. **Paths may be typed, not only picked.** The UI offers discovered projects,
   and it also accepts an arbitrary directory the user enters. Rules 1 and 2
   apply identically to both — a typed path is not a lesser input, it is the
   same input from a different widget.
4. **Outside `$HOME` remains file-only.** Serving a path outside `$HOME` stays
   possible by editing `server.toml` directly. The file is the escape hatch, and
   it stays the only one.
5. **The node still writes the file it watches.** UI edits go to `server.toml`;
   the existing watcher picks them up. [ADR-0077 — The node serves an explicit allowlist; discovery only suggests](ADR-0077.md)'s property that there is no second
   write authority survives intact — only the set of things that may author that
   file grows.

This amends [ADR-0077 — The node serves an explicit allowlist; discovery only suggests](ADR-0077.md) on one point: "no endpoint accepts a filesystem path"
becomes "no endpoint accepts an *unvalidated* filesystem path, and validation is
`$HOME`-containment plus the hidden-component rule". Everything else that ADR
decided — the allowlist as the unit of service, discovery that only suggests by
default, the bounded background scan, the closed action enum — stands unchanged.
[ADR-0077 — The node serves an explicit allowlist; discovery only suggests](ADR-0077.md) is left `accepted` rather than `superseded` because the
majority of it is still the operative decision; a reader needs both.

**[BUG-0084 — A project's inventory base can escape its root](BUG-0084.md) was a prerequisite and is now done.** Rules 1 and 2 constrain
which directory is allowlisted and say nothing about where that directory's own
config then points, so shipping UI management before base containment would have
handed the escape a remote trigger. `ProjectConfig::resolve_base` closed it.

## Consequences

The dashboard becomes self-sufficient for the task it exists to support, and the
"installed it, now SSH in to use it" seam closes. [FEAT-0042 — Remote MCP: manage the registry from shell-less hosts](FEAT-0042.md) narrows to what
it is actually for — reaching a node from a host that has no browser either —
rather than being the only route to registry management.

The cost is that the node now has a validated path-accepting endpoint where it
had none, so the validation is security-critical code and has to be tested as
such: `..` traversal, symlinks out of `$HOME`, dot-components at every depth, a
`$HOME` that is itself a symlink, and the empty/relative/absolute spellings. A
bug there is a boundary failure, not a papercut.

`$HOME`-containment is a policy about where a *user's* projects live, and it will
occasionally be wrong — a repo on a second disk, a shared `/srv` checkout. Those
users edit `server.toml`, which is the same thing they do today, so the feature
takes nothing away.

A human stays in the loop for every addition. An auto-add mode was drafted for
[FEAT-0083 — Scan modes and first-run onboarding](FEAT-0083.md) and cut: it would have removed the person from the one step
that matters, since allowlisting a project is what causes it to be *opened*, and
opening it is what reads whatever its `opys.toml` points `base` at. Once
suggestions are in the UI rather than behind an SSH session, the saving is a
single click and the cost is the property this whole ADR is trying to preserve.

That cut also demotes [BUG-0084 — A project's inventory base can escape its root](BUG-0084.md) from prerequisite to hygiene here: a
person sees the path before anything opens it, so an escaping `base` cannot be
reached without someone accepting the project carrying it. The bug is fixed regardless — an accepted project
should not read or write outside its own root either — but it no longer gates
this decision.
