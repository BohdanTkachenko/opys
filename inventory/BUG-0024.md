# Multi-line string fields corrupt on re-serialization

## Reproduction
Give a doc a declared string field with a block scalar (`spec: |-` + two lines), then run any mutating command, e.g. `opys tag FEAT-0001 --add d`. The command exits 0 and writes `spec: line one\nline two` inline — invalid YAML; the doc becomes unparseable and sync is skipped. The keep-`\n` variant is double-quoted with a raw newline, which YAML folding silently turns into a space. `frontmatter.rs` `inline_scalar`/`needs_quote` never check for embedded newlines, violating the round-trip invariant format.md promises.

## Tasks
- [ ] emit block scalars (or escaped quoting) for strings containing newlines in `frontmatter::serialize`
- [ ] add a round-trip unit test for multiline block-scalar fields
