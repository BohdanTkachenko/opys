# opys-server: worktree union view

The one genuinely novel M1 feature: a merged, **labeled** view across the
corpora of one project group (main + worktrees). Presentation of divergence
only — the server never merges or resolves anything ([ADR-0051 — Files and git are the only truth; the server is a view](ADR-0051.md)); git remains
the only merger. This view is deliberately the seed of [FEAT-0063 — Teams: node mesh, union view, per-seat plan](FEAT-0063.md)'s team union
view (branch/node overlays are the same shape), so keep the merge logic a pure
function over per-corpus summaries.

Spec:

- Pure fn in `opys-server/src/union.rs`:
  `fn union(corpora: &[(Corpus, Vec<DocSummary>)]) -> UnionView` where
  `UnionView = { columns: [{cid, label /* branch or dir name, "(primary)"
  marker */}], rows: [{id, title /* from the primary if present, else first
  */, cells: [{cid, status?: String, updated?: String}], differs: bool,
  only_in: [cid] }] }`.
  - Row set = union of doc ids across corpora, ordered by numeric id part.
  - `differs` = true when present in ≥2 corpora with differing status OR
    title.
  - A duplicate *number* across different ids (impending collision —
    [FEAT-0017 — renumber: cross-branch ID collision repair](FEAT-0017.md)'s territory) gets `collision: true` on both rows.
- Route: `GET /api/group/{key}/union?type=&status=` — gathers `Docs` from
  each member actor (filters applied per corpus first), runs the pure fn.
  404 for an unknown group; a single-corpus group returns the trivial
  one-column view (valid, not an error).
- Unit tests on the pure fn: absent-in-one, status-drift sets `differs`,
  number-collision flag, ordering. One handler test over a two-corpus
  fixture group.

## Progress
- Filed as part of the M1 plan (see [FEAT-0058 — opys-server: the always-on node](FEAT-0058.md)'s Plan section).
- 2026-08-24: implemented. `opys-server/src/union.rs` is the merge, and it is
  genuinely pure — no filesystem, no network, no axum, no tokio, nothing about
  actors — so [FEAT-0063 — Teams: node mesh, union view, per-seat plan](FEAT-0063.md) can feed it summaries that arrived from a remote
  node instead of a local worktree without touching it. `GET
  /api/group/{key}/union` gathers each member's docs (filters applied per corpus
  first) and runs it.
- Three additions to the documented shape, each earning its place. A `Cell`
  carries `title` as well as `status`, because `differs` is defined over both and
  a table that flags a difference it cannot show is useless. A `Cell` also
  carries `unknown`, which separates *this corpus does not have that document*
  from *this corpus did not answer* — a column whose actor is mid-reload or
  broken must not silently read as "deleted here". And a `Column` carries an
  optional `error` so that failure is attributable to the worktree it came from.
- Dogfooded against a real git repo with a second worktree on `feature/x`,
  deliberately diverged: a renamed title, a status drift, a doc written only on
  the branch, and two *different* ids sharing number 0004 across the two
  worktrees. Every flag landed where it belonged — `differs` on the renamed and
  the drifted rows, `only_in` on the one-sided ones, `collision` on **both**
  halves of the number clash — and the columns came back labeled `main
  (primary)` and `feature/x`. The single-corpus case returns a valid one-column
  view rather than an error, so a UI needs no second code path, and an unknown
  group key is a 404 in the standard error shape.
- **One semantic that needs UI copy, not a code fix.** Filtering the group by
  status hides the *other* copy before the merge, so filtering by `status=doing`
  renders a task that is `doing` on main and `done` on the branch as
  `differs: false, only_in: [main]` — the drift the view exists to show
  disappears precisely when you filter for one side of it. Filtering per corpus
  before merging is what the spec asks for and is the only thing that can scale
  to remote overlays, so the handler documents the consequence and
  [TASK-0074 — opys-server: embedded web UI](TASK-0074.md) carries the obligation to say it in the interface.
- Adversarial review returned 16 findings, 8 major, all triaged and the real ones
  fixed. Two notes deliberately left alone: unknown query keys are ignored
  silently, which matches what `/api/corpus/{cid}/docs` already does (consistency
  beat novelty), and `refs::id_number` uses `u64::MAX` as its unparsable
  sentinel, so a hypothetical `FOO-18446744073709551615` would skip the collision
  check — `union.rs` guards against it and no allocator can produce that id.
- Tests: 5 in `tests/union_api.rs` plus the pure-function unit tests, every
  required case mutation-checked. The seven pre-existing server test files are
  untouched. Full CI gate and `msrv` green on a forced recompile.
