# opys-server: worktree union view

The one genuinely novel M1 feature: a merged, **labeled** view across the
corpora of one project group (main + worktrees). Presentation of divergence
only — the server never merges or resolves anything ([ADR-0051 — Files and git are the only truth; the server is a view](ADR-0051.md)); git remains
the only merger. This view is deliberately the seed of [FEAT-0063 — Teams: node mesh, union view, per-seat plan](FEAT-0063.md)'s team union
view (branch/node overlays are the same shape), so keep the merge logic a pure
function over per-corpus summaries.

Spec:

- Pure fn in `opys-server/src/union.rs`:
  `fn union(corpora: &[(Corpus, Vec<DocSummary>)]) -> UnionView` where
  `UnionView = { columns: [{cid, label /* branch or dir name, "(primary)"
  marker */}], rows: [{id, title /* from the primary if present, else first
  */, cells: [{cid, status?: String, updated?: String}], differs: bool,
  only_in: [cid] }] }`.
  - Row set = union of doc ids across corpora, ordered by numeric id part.
  - `differs` = true when present in ≥2 corpora with differing status OR
    title.
  - A duplicate *number* across different ids (impending collision —
    [FEAT-0017 — renumber: cross-branch ID collision repair](FEAT-0017.md)'s territory) gets `collision: true` on both rows.
- Route: `GET /api/group/{key}/union?type=&status=` — gathers `Docs` from
  each member actor (filters applied per corpus first), runs the pure fn.
  404 for an unknown group; a single-corpus group returns the trivial
  one-column view (valid, not an error).
- Unit tests on the pure fn: absent-in-one, status-drift sets `differs`,
  number-collision flag, ordering. One handler test over a two-corpus
  fixture group.
