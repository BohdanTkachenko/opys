# engine: `opys log` and dated log sections

[FEAT-0105 — `opys log`: append a dated entry to a log section](FEAT-0105.md). Depends on [TASK-0114 — engine: remove `query --write` and the writable blocks projection](TASK-0114.md) so the section splice has one owner.

Spec:

- `commands/log.rs`: `log <id> <text|->` with `--section`. Resolve the `log`
  section from the type's declared sections; zero is exit 2, two without
  `--section` is exit 2. Append `- <UTC ts> <text>` through
  `apply_section_edits`; stdin text is indented as continuation lines. Then
  `touch` and `maybe_sync`.
- The `log` kind gains parsing: `body::log_entries(section) -> Vec<(ts, text)>`
  where an undated bullet yields `None` for `ts`.
- Verify: undated bullets and non-monotonic timestamps in a `log` section are
  problems.
- Rules: `require_log_since_status = "<heading>"` asserts an entry newer than
  the last history key. Shipped config uses it `when = { type = "task",
  status = "review" }` and likewise for bug and chore.
- The node's action enum gains `Log { id, text }`; the document view gets an
  entry box.
- Skill: the agent rule tells agents to log through the command, never by
  editing the section.
