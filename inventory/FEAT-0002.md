# Global never-reuse ID sequence and retired ledger

IDs are drawn from a single global, monotonically increasing sequence shared by every type. A number is never reused: allocation takes the max over live docs, the `_retired.md` ledger, and every relation map (struck or not). `retire` and `close` append to the sorted ledger (the reservation of record — tombstones in relation maps are presentation); `cleanup` ledger-reserves any id whose last tombstone it strips; `verify` rejects reuse and duplicate numbers. An unreadable ledger (markdown or legacy plaintext) is an error that blocks allocation, reservation, and flush — never an empty read.

With `[ids] modulus = M` set in `opys.toml`, the sequence is interleaved ([ADR-0103 — Interleaved id sequences replace lease blocks](ADR-0103.md)): each allocator owns a slot in `0..M` — `OPYS_ID_SLOT`, else a stable FNV-1a hash of `user@host` modulo `M` — and takes only the numbers congruent to it above the same corpus-wide max, so allocators on different branches never collide without any shared ledger or ref. `import` and `renumber` reserve one block that steps by `M`; a slot outside the modulus is a usage error, a modulus below 2 (or above `2^32`) a config problem, and an unknown `[ids]` key a parse error. Without a modulus, allocation is the dense sequence, byte-identically, and `OPYS_ID_SLOT` is not read.
