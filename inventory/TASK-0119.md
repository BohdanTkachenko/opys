# opys-server: ref reader, occupancy in the union, `next` endpoint, autofix

[ADR-0101 — Verify observes time: stuck, visits, `--fix`, and exit code 3](ADR-0101.md) decision 6 and [ADR-0102 — Branches are progress, main is truth](ADR-0102.md) decision 5.

Spec:

- A `RefReader` per project group: a thread that calls `git::occupancy` on
  start, on a change under the git dir's `refs/`, `packed-refs` and
  `worktrees/*/HEAD` (one `notify` watcher, 250 ms debounce), and every 60 s as
  a backstop. It publishes `Event::RefsChanged { project }` and holds the last
  result behind the manager.
- The union gains columns for refs with no worktree, built from
  `docs_changed_vs_main`; `Column.error` semantics apply when the reader
  failed. Rows carry occupancy.
- `GET /api/projects/{p}/next?status=&type=&n=` calls `next::pick` and returns
  the CLI's JSON shape verbatim.
- Autofix: the actor's verify pass computes observations; when `autofix` is
  true (default), the manager performs `verify --fix` semantics as an
  ordinary action cycle (own `Project` and `Store`, the flock, never the warm
  store), one per corpus per reload, and emits `action-completed` with action
  `autofix`. `server.toml` gains `autofix = false` to disable. Document in the
  README's node section with real output.
- The verify dot gets a third state for `autofix = false`.
- Tests: an occupied branch appears in the union without a worktree; a stuck
  document in a fixture corpus is fixed by the node within one reload and the
  CLI sees the transition; `autofix = false` leaves it and the API reports the
  observation.
