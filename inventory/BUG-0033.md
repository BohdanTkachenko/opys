# unblock reverts to a hardcoded in-progress status

## Reproduction
Task at `todo` → `opys block` auto-sets `blocked` → `opys unblock` lands it at `in-progress`, never back at `todo`. For a type with a `blocked` status but no `in-progress`, unblock leaves the doc at `blocked` with no blocker or reason — which then fails the blocked rule in verify.

## Tasks
- [ ] remember the pre-block status (field or ledger) and restore it on unblock
- [ ] handle types without `in-progress` gracefully
- [ ] test unblock from todo and on a custom status set
