# Section checks: test-plan traceability

Any section can carry config-driven checks: a `pattern` regex parses each line into named capture groups; an optional `file` group asserts a path exists under `roots`, and/or a `must_match` regex (built from `${group}` substitutions) asserts the reference resolves in the corpus or the codebase. The default config uses one such check to require every checked Test-plan item to name a real test — the mechanism that keeps this very document honest.
